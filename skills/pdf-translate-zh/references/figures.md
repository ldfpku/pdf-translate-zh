## 1. 先分类：按**能不能提取**分三类，处置完全不同

| 类 | 判别 | 处置 | 工具 |
|---|---|---|---|
| **A 矢量真文字** | `get_text()` 里有 | redaction 抹除 + 原位写中文 | `hybrid_overlay` / `dwg_overlay` |
| **B 描边曲线** | 文本层无；`get_drawings()` 里是密集小路径 | 按笔画连通块定位 → 铺底写中文 | `vectext.runs()` |
| **C 位图烧死** | 文本层无；落在嵌入位图的 bbox 内 | 粗框 → 墨迹框 → 铺底写中文 | `vectext.inkbox()` + `genraster.py` |

判别代码：

```python
big = [fitz.Rect(im["bbox"]) for im in page.get_image_info()
       if im["bbox"][2]-im["bbox"][0] > 140 and im["bbox"][3]-im["bbox"][1] > 70]
ntxt = sum(1 for w in page.get_text("words")
           if any(b.x0 <= (w[0]+w[2])/2 <= b.x1 and b.y0 <= (w[1]+w[3])/2 <= b.y1
                  for b in big))
# ntxt == 0 且 big 非空 ⇒ 该区域可能藏有 C 类
```

## 3. C 类流水线（五步，缺一不可）

```
① 渲染**源图**读粗框，连译文写成 rNN.py
     ROUGH = [(x0, y0, x1, y1, "中文", 转角), …]
② python genraster.py <0基页号> <rough模块>
     → vectext.inkbox() 批量把粗框收成墨迹框
     → 生成 raster_zh_pNN.py，同时**画框出图**
③ 目检画框图：框不许碰到插图本体、不许漏掉词尾
④ 挂进 build.py 的 RASTER_ZH → 构建
⑤ 出图复检 → 六道关全量体检
```

### `inkbox` 为什么比连通块分析可靠

`vectext.snap()` 走「连通块 + 同行合并」，对**下采样过的位图小字**不稳：
实测 手册 A 第 11 页 26 条标注里有 **24 条只吸附到单个字符**（2~3pt 宽）。

`inkbox()` 换一条更笨也更可靠的路：**粗框内所有深像素的包围盒**。
前提是粗框里只有那一条标注、其余是白底 —— 这个前提由「画框目检」保证。

```python
def inkbox(page, rough, dpi=220, thresh=170, pad=0.6):
    pm = page.get_pixmap(clip=rough, matrix=fitz.Matrix(dpi/72, dpi/72),
                         colorspace=fitz.csGRAY)
    # 取 samples 里 < thresh 的像素的包围盒，换算回 PDF 坐标
```

## 4. **四条硬教训**（每条都实测栽过）

### ① 必须拿**源 PDF** 量

成品页上已经铺了白底、写了中文。再去量「深像素包围盒」，量到的是**中文自己**，
框会越量越小。实测第 12 页第二轮重量后所有框缩成 2~4pt，48 条标注全废。

```python
d = fitz.open(SRC)      # ← 源文件，不是成品
```

位图在源页与成品页**同位同尺**，坐标直接通用。

### ② 带黑边框的标注，粗框要**先内缩**

`Rubber Catch`、`Adjustable & Double Key Adjustable (DKA)`、
`Fixed Bent Housing` 这类标注外面有黑框。粗框若含到框线，
包围盒就把框线包进来 —— 铺底时连框一起盖掉，图上凭空少一个方框。

⇒ 粗框读到**框线内侧**，或事后按 1.5~2pt 内缩。

### ③ 竖排标注要给**转角**

`overlay(items)` 的第 5 元素是转角。不给就横着写、直接出框。
实测 手册 A 第 11 页 `Keyed – Double Key and Splined Mandrels`、
第 12 页 5 条（胶塞/转子/橡果形打捞头、转子接头、柔性轴）与
1 条竖排长句（整套细节见装配程序）。

转角一给，`overlay` 内部就把「行长」取框高、「堆叠深度」取框宽。

### ④ 粗框**宁大勿小，但不能碰插图**

- 小了 → 留词尾词首残片。实测 5 处：`ng`（`Housing` 的尾）、`Be`（`Bearing` 的首）、
  `(DIVE`（`(DIVERTER ADAPTER ONLY)` 的首）、`t`（`Seat` 的尾）、`3`（`3 places` 的首）。
- 大了 → 包围盒被图元拉开，白底盖住插图。

肉眼从缩图上读坐标**常差 40pt**（实测 手册 A 第 51 页 `Sharp Edges`
我一次读偏了 44pt）。拿不准就用 `vectext.raster_runs()` 在小区域内实测：

```python
rs = vectext.raster_runs(page, clip=fitz.Rect(255,480,320,510), dpi=260)
# → [[261.6, 489.4, 296.8, 494.4], …]  真实墨迹框
```

## 5. 底色：白底 vs 彩底

默认铺白底。但图内标注常印在**彩色块**上 —— 这时必须按该块的底色铺、
并用白字写，否则会在彩带上留下一块白疤。

实测 手册 A 第 7 页七条安全要求是**白字彩底**，逐条按源图采样的底色铺：

```python
RASTER_ZH = {6: [
    ((124.5, 285.0, 507, 316.4), "了解你的工作岗位需要哪些工装、设备与个人防护装备（PPE）。",
     (255/255, 0, 0), (1, 1, 1)),      # (底色, 字色)
    …
]}
```

**两趟画**：先铺完所有底衬，再统一写字。逐条「画底衬→写字」时，
下一条的底衬会盖掉上一条的字脚（多行标注表现为「文字显示不全」）。

## 6. 图内文字的**分级处置**

| 保留不译 | 译出 |
|---|---|
| 尺寸代号：`ØA` `ØB` `ØC` `ØD` `D` `G` `B` `V to C` | 零件名、部位名 |
| 件号数字（1~2 位）、`T1` `T2` | 说明性标注 |
| 商标／型号：`Brand-X` `Model-Y` `XYZ` `IB` `Lok-Tite` | 判据文字 |
| 纯数值＋单位：`3000 psi` `0.020"` | 斜体注记（按含义译，见下） |

**斜体注记**在工程图里是「处置结论」，必须译：

| 原文 | 译文 |
|---|---|
| `- Recut -` | — 重新车扣 — |
| `- Reline -` | — 重新衬胶 — |
| `- Rechrome -` | — 重新镀铬 — |
| `- Grind -` / `- Grind smooth -` | — 打磨 — / — 磨平 — |
| `- Grind or Recut -` | — 打磨或重新车扣 — |
| `- Scrap -` | — 报废 — |

## 7. A 类（矢量真文字）的两条老规矩

- **同一标注可能叠印多份**。原版常把一条标注按不同字号叠印 2~5 份
  （实测同一条 7.92pt + 9.55pt 各一份）。英文完全重合、肉眼无异常；
  换成中文后宽度不同，立刻露出双重影。
  ⇒ 判重键为「文本相同 + 位置相差 < 3pt」，保留字号最大的一份。
  **别按纯文本去重** —— 一幅图里「扭矩套」「此处夹紧」本就会出现多处。
- **字号自适配**：中文常宽于原英文框，按 `原框宽 × 1.08` 收缩（下限 4.6pt）。
  表单勾选框用 `□`，**不要**用 `（  ）` —— 全角括号太宽，必然撞线。

## 8. 从零重建路线的插图剪裁

（叠印路线不需要剪裁 —— 图原样留在页上。以下只对**从零重建**适用。）

```
图形簇 = 矢量绘图 + 嵌入位图
        − 纯白画布矩形         （避坑 ①）
        − 修订变更条           （避坑 ②）
        − 落在表格框内的图元   （表格由代码重建，绝不入图）
        − 压在正文行上的零星图元
        − 面积 > 35% 版心的异常巨框
纵向聚类：间距 < 26pt 合并，但严禁跨越「真实文本行」
断图拼接：横向重叠 > 80%、纵向间隙 < 45pt、且间隙内无文本 → 合并
边缘修剪：仅修剪压在上/下 18% 边带的正文行
输出：整幅嵌入图按 xref 原分辨率；碎片图按 ≥300dpi 区域渲染
```

**顺序不能错**：先修边 → 再拼接 → **复修边**。先拼接时簇框里还含着上方
项目符号等正文残留，会让「合并后不吞文本」的判据永远失败，同一幅图始终被拆成两半。

**发丝线要自适应分辨率**：工程图常见 0.12pt 级线宽，小图按 300dpi 渲染时
线宽不足 1 像素，被抗锯齿糊成浅灰。⇒ 图宽 ≥250pt 用 300dpi、
120~250pt 用 450dpi、<120pt 用 600dpi。

剪裁后**必须**出 contact sheet 目检；每格标注 `p页#序 L标注数 N件号数`。
再补一条**机器判据**：每幅裁图与「源页同 bbox 参考图」逐像素比对
（参考图墨迹按 ±2px 膨胀，阈值 8%；抗锯齿差异 ≤2%，取错页面 ≥50%）。

## 9. ⚠ 裁框范围：**位图 bbox 不等于图的视觉范围**（`figcrop.py`）

带引线标注的图（爆炸图、部件示意图、操作步骤图），标签文字与引线常是
页面上**独立的文本/矢量对象**，画在嵌入位图 bbox 之**外**。
直接用 `get_image_info()` 的 bbox 去裁，两类事故都会发生：

| 事故 | 表现 |
|---|---|
| **标注被腰斩／整条漏掉** | 裁图上留断头的方括号引线、半个字的残影；交付后读者才发现部件标签缺失 |
| **裁框蹭到相邻正文** | 图正上方露出一截无关英文（实测「…float valve.」行尾被刮进裁图） |

⇒ 用 `figcrop.safe_extent(page, img_bbox)`：

```python
ext, hits, warn = figcrop.safe_extent(page, img_bbox)
# ext  : 含全部标注、又不沾正文的裁框
# hits : 每条标注的**源 PDF 坐标** —— 回叠时直接用，见 §10
# warn : 非空＝仍有沾边/腰斩，调用方须处理（铺白或人工核实）
```

### 判据设计的五条硬教训（都实测栽过）

**① 「正文 vs 标注」不能只看字号或粗体。** 小标题常是「加粗引导词 +
同号正文」，粗体分不出；标注也可能与正文同号。⇒ 三条独立判据取并集：
字号贴近**局部**正文基准 ∪ 所属**块**顶格在栏左边界 ∪ 图题前缀。

**② 「局部」两个字是关键。** 统计正文基准字号时若按整页算，同页只要有
一张密集参数表（十几行 5.5pt 数字）就能在数量上反超几行真正文，
5.5pt 被判成「正文基准」→ 真正 9pt 的正文整页被当成「图内标注」→
裁框膨胀到原图 **11 倍**。⇒ 统计范围限定在该图周边窗口。
同理不能按**字符数**加权——表格单元格字符多、每格却只三五个字符。

**③ 顶格判据要按「块」不按「行」。** 标题换行后的续行本身未必顶格
（居中标题、悬挂缩进都会），只要同块里有任意一行顶格，整块即为正文。
栏左边界要取**出现次数最多的前 N 档**，不能「挨得够近就算」——
实测某标签 x0=311、真栏界 x0=315，只差 4pt，宽容差就误伤。

**④ ⚠ 求范围要「从图心向外逐个吸附」，不能一次性求并集。**
一次性并集时，任何一个被误判的远处候选都会把裁框一次性拉穿整页，
且事后无从分辨是哪一个（实测把邻栏整张表格 + 小节标题全吃了进去）。
逐个吸附则天然有序：按到当前裁框的距离从近到远，一旦某个候选的间距
超过 `gap_max`（默认 26pt），说明它与本图之间隔着空白、不属于本图，
后面更远的更不属于，**直接停手**。真正的引线标注必然紧贴图排布。

**⑤ 判据必须有硬上限。** `max_area_ratio`（默认 4.0）超了就退回原始
位图 bbox 并报警，不再自动调整。判据失灵是会发生的——宁可停手报警，
也不能让一个跑飞的结果悄悄进成品。**不设上限的判据，错起来比没判据还离谱。**

## 10. 图内标注回叠：坐标必须与裁框**同源**（`figlabel.py`）

⚠ **绝不要手估像素框。** 手估坐标与实际裁框来自两次独立判断，
裁框哪怕微调 2pt，全部标签就整体错位。

⇒ 裁图时把 `hits` 换算成裁图内像素坐标落盘（`labels.json`），
回叠时直接读——两者同源，天然一致：

```python
# 裁图脚本：ext 与 hits 来自同一次检测
px = [(r - (ext.x0, ext.y0, ext.x0, ext.y0)) * zoom for r, _t in hits]

# 回叠脚本：内容层只提供译名，坐标一概不碰
figlabel.apply_manifest(figdir, {"Top Sub &": "上接头与", ...})
```

**位图烧死的标注**（不在文本层）用 `figlabel.detect_raster_labels()`
按连通域找框——机器只能告诉你「这里有字」，读不出「写的是什么」
（无 OCR 时）。故框由机器给、译名由人填，坐标仍不是手估的。

### 五条实操约束

- **跑序**：`crop → sweep → translate`。裁图会覆盖 png、抹掉上一轮叠的
  中文——这是**有意为之**：始终从干净原图描白，避免反复叠字产生重影。
  跑反了等于没译。
- **源图把一个标签拆成上下两块时**（`Offset` / `Housing`），要合并成
  一个框整体重写，否则中文被硬拆成两行，读着别扭。合并不了的（检测
  给了两个框），首框写完整中文、续行框给**空串译名 = 只描白不写字**。
  ⚠ 空串与「未收录」语义不同：判断必须 `is None`，用真值判断会把
  空串条目当 miss 跳过，计划抹白的英文残段全部留在成品里（实测）。
- **图内英文图题一律不得见于成品**（中文图题由正文 caption 承担）。
  矢量图题（含折行续行与外框线）由 `figcrop` 在裁剪阶段整块排除 +
  禁区钳位挡在框外（§9）；只有**烧死在位图像素里的图题**才需要描白
  剔除，且剔除范围必须连图题外框线一起盖掉——只擦文字会留一个空壳。
- **裁框规则变更后，基于旧裁图的像素坐标即刻作废**：图题改为裁剪
  排除后裁图变矮，遗留的旧描白区会抹掉真图形（实测差点抹掉总览图的
  钻头下端）；ext 尺寸跨过 dpi 档位阈值时坐标整体换算。重裁后必须
  跑 sweep 用蓝框逐幅核对旧坐标是否仍对齐。
- **描白避让图形语言**：检测框若把尺寸引线折角、箭头一并圈进
  （`⌐WEAR`），照框描白会把引线抹掉——收窄到文字本体再写译名。

### 10.1 R 级的最短路径：`LABELS_ZH` + `figlabel.apply_figures_json`

`extract.py` 裁图时已把图内**矢量**英文 redaction 掉，并把每条标注在裁框内的 pt 坐标
记进 `data/figures.json` 的 `labels`。内容层只需在 `content.py` 写
`LABELS_ZH = {英文: 中文}`（保留项写成与原文相同；空串 = 只描白不写字），
`build.py` 构建时自动按同源坐标回叠（首次备份干净底图到 `figures/_clean/`，重复构建
不叠重影；重新提取会作废备份）。覆盖判据「图内标注中文覆盖」必须为 0。
位图烧死的 C 类标注不在 figures.json 里，仍按 §2~§3 逐幅全查。

## 11. 漏译排查必须逐幅全查（`figlabel.sweep`）

旧排查法「含嵌入位图 **且** 矢量标注数 = 0 的图才查位图英文」有判据
漏洞：只要检出 1 条矢量文本——哪怕只是英文图题的折行残行——整幅图
就躲过位图排查。实测一幅三联对照图：1 条矢量图题 + 13 条位图标签
**整幅漏译**，旧判据完全放行，直到用户指着成品图问「图里的字怎么没译」。

```python
left = figlabel.sweep(png, covered, out_path=qa_png)
# covered = 矢量回叠框 ∪ 位图重写框 ∪ 白名单保留区
# left    = 未处置文字块 → 描红输出核查图，人工逐幅确认
```

- 真漏译 → 补译名；合法保留（纯数字、单位、尺寸字母、箭头等图形
  语言）→ 录入 KEEP 白名单**并注明是什么**，复跑到 0；
- 这是**常驻闸门**：`crop` 之后、`translate` 之前每次都跑；
- 核查图上同时画出 covered（蓝框）——蓝框是否仍与文字严丝合缝，
  就是「旧坐标经重裁后是否失效」的直读判据。

## 12. 图幅版面权重：尺寸也是内容

原版给一幅图多大版面，是出版人的表达。占一页的整机总览图被排成
半栏小图——信息没丢，**视觉权重丢了**（实测被用户点名退回：
「人为缩小尺寸，有违出版人本意」）。两条规则：

- **下限**：输出宽度 ≥ 源版物理宽度（含标注的 ext 宽度）。语义重排
  后版心变宽是常态，图跟着放大无妨，缩小要有明确理由并记录；
- **占页图**：原版独占一页大部的图（整机总览、大型装配图），译版
  同样给它一页——按「版心高 − 图题高 − 间距」反推上限宽度，
  通常取源版物理尺寸即可占满。

**图题独行**：图题**不入图宽列**。图题的可用宽度是版心宽，不是图宽——
跟随图宽时，窄图的图题必然被无谓折行（实测 90pt 图宽列把 13 字图题
折成两行）。`render.py` 的 fig 块已改为
`KeepTogether([图表格, Spacer, 版心宽居中图题])`，能一行排下就一行，
且图与图题永不分页。

## 13. 图-图题配对：真值布线制（V3，避坑 73）

重排路线下图与图题会分离：抽取器把 [FIG] 占位放在页首、图题文本却在
阅读流位置。**按阅读顺序就近配对，一处错配即全章级联**——实测 图4.0
配错后 4.1~4.5 全部串位，直到用户点名。

⇒ 配对必须从**源版几何**取真值，一次性显式落盘：

```
① 源版扫描：每条 "Figure/Table N.M" 图题行 → 同页、图底 y 邻接
   （-20 < 图题y0 − 图ext.y1 < 200）的裁图 → cap_assoc.json
② 人工核定歧义项（图题与图不同页的、一页多图多题的、表题配烧死表格的）
③ 重布线：译稿中的图题块原位替换为 figc{图名, 图题}；裸 fig 块全删；
   未配题的图以 figc(无题) 按源阅读位置保位
④ 装配层只认 figc，零启发式
```

交付前后的常驻对账：**每条「图/表 N.M」所在输出页的图数清单**——
串位、丢图、双图题一眼可辨（0 图的图题行必须能解释：由重建表承载）。

⚠ **图题的折行续行 bbox 必须并进图题框**（避坑 100）。真值布线用
「上一条图题之下、本条图题之上」定一幅图的范围；若图题框只取首行，
「上一条图题之下」就停在首行底，图题**第二行整条落进下一幅的裁框** ——
实测某图顶上横着上一幅的副题「Re-setting NAMCBPV at the rig to start position」。
且并行的余量要收小：实测图题末行底与下一幅第一条标注之间只差 **1.1pt**，
沿用「图题底 +6pt」会把人家的标注挡在标注带之外。

## 13.5 ⚠⚠ 裁框净空：图与图题之间不许留残迹（`figclip.py`，避坑 100）

**这是全套闸门都看不见的一类缺陷，也是用户目检第一眼就会看到的。**

裁一幅图有三个坐标来源 —— 位图 bbox、矢量簇并集、标注外扩。
三者都只描述「图画到哪里」，**没有一个知道英文图题在哪**。
再各加几 pt 余量（`+3` 的标注外扩、`PAD=4` 的渲染留白），裁框就顺势吃进
图题顶端几 pt：成品上是一条「Figure 4-7」的上半截，横在中文图题正上方。

**为什么闸门全绿**：图题随位图裁进去了，它在成品里是**像素**不是文本，
残留英文关扫的是文本层；而在源页上它**是**文本 —— 只是从没有人去查
「裁框和它相不相交」。实测规模：某册 24 幅插图中 **16 幅**、第 7 节 22 张
现场照片中 **12 张**、另一册 6 幅中 1 幅。用户点名 2 幅，真实规模 29 处。

判据与算法：

```python
import figclip
clip, moved, warn = figclip.clearance(page, clip, keep=KEEP_RE.pattern)
left = figclip.residual(page, clip, keep=KEEP_RE.pattern)     # 必须为空
```

`clearance` 只在**离框心近的那一侧**向内收（图题在下就抬底边、上一条图题
在上就压顶边），收得比 `minfrac` 还狠说明这个框本身就定错了 —— 照收，
但把警告抛给调用方，不静默。

四条必须知道的：

1. **不能用 `page.get_text(clip=)` 求「框内还有什么字」。** MuPDF 对 clip
   用的是部分包含判据：实测同样是图题顶端，4.8pt 落在框内会返回、
   2.7pt 就不返回。判据自己漏报比没有判据更糟（避坑 59）
   ⇒ 取整页 span 自求矩形相交。
2. **已含中文的 span 一律不算残留。** 译文里本就嵌着 TMP／NC／O-ring 这类
   保留原文，实测「标准 TMP 斜向器总成」被当成残留英文，裁框一路收到
   源高的 52%。
3. **先撑开、再收紧，收完回头验中文没被切掉。** 中文比英文短窄是常态，
   但「（与斜向器背面齐平）」这类整句会比原文宽；裁框是按**英文** span 算的，
   不撑开就切掉半个字。撑开与收紧是两股相反的力，末了要断言
   `zh_extent ⊆ clip`。
4. **裁框要写盘。** 各插图流水线把最终裁框记进 manifest，闸门读回来复验
   （`checks.check_fig_clip`）—— 裁框一改，判据自动跟着改，不会各说各话。

同一条规矩对**现场照片**同样适用：源版把英文步骤说明压得极紧，实测 22 张
照片的裁框里有 12 张各吃进相邻说明行 1~2pt（降部／升部那一截）。

## 16. 插图画质修复：先量有效分辨率，再超分（V3.1，某客户 SWI 作业指导书实战）

### 16.1 判据与流程

**有效分辨率 = 像素宽 ÷ 版面放置宽(pt) × 72**（`sr.effective_dpi`）。系统导出的手册常只有
85 dpi（实测 某客户 SWI 作业指导书 整册 38 幅 510 px / 430 pt），成品放大即糊，气泡里的数字发虚。

```
提取原图（figures_src/，SMask 合成）→ sr.py 超分 4 倍（figures_sr/）→ 标注检测/回叠/气泡重绘（figures/）
→ 大图 JPEG q92 4:4:4 嵌入（2040 px ≈ 340 dpi），徽标/图标 PNG
```

- **先超分再检测**：白底检测在 4 倍图上更稳，中文以 4 倍分辨率写入；检测参数按 4 倍口径
  （字高 32~44 px：`max_h=70, word_gap=52`；引线并入的图改 `word_gap=26` 重检）；
- ≥ 300 dpi 的原图不动，超分只添伪影；极小徽章（13×13 px）可做两遍（16 倍）；
- Real-ESRGAN x4plus（RRDBNet，`sr.py`，权重 67 MB 自动下载并校验，RTX 显卡整册 12 秒）。后端按本机条件自动选：
  torch（CUDA / Apple MPS / CPU）→ onnxruntime + ONNX 模型（`sr.py --export-onnx` 导出，与 torch 逐像素一致，
  CPU 上还略快）→ **Lanczos 兜底**（不是超分，只保证流程不断；`sr_report.json` 会记下，丙里必须照实写）；
  对 CAD 渲染图、线条图效果稳定，照片亦可；
- 处置写进附录 A 丙：超分倍数、几何与色彩不作改动。

### 16.2 ⚠ 带软掩膜的徽标不要超分（避坑 106）

封面客户徽标：基色图只有 83×58 px，边缘全由 **1350×950 px 的 SMask** 定义。
按尺寸相同才合成的写法会跳过它，提取出来是**黑底糊图**；超分也只是把糊图放大。
⇒ 基色图 resize 到掩膜尺寸再 `putalpha`，白底合成 —— 得到的是原始矢量级边缘。
提取时一律读 `extract_image(xref)["smask"]`，尺寸不同就 resize 基图。

### 16.3 超分图上的标注回叠（`tightbox.tighten`，避坑 107）

检测框并框后常含引线、箭头头、相邻零件碎片。五条规则（每条对应一次实测失败）：

| 规则 | 失败现场 |
|---|---|
| 细**且长**（h<9 或 w>4h，且 w≥18）= 引线；紧贴它的小块 = 箭头头，一并剔除 | 整框描白抹掉引线（x48） |
| 1 px 噪点**不算**引线 | 噪点紧邻 "y"/"A"，字母被连坐剔除，成品留残字 |
| **不按横长比过滤单字母** | "W"/"e"/"n" 横长比 <1.25 被丢，留下 "END VIE"+"W" 残字 |
| h>64 px 的是图形 | 阀体、泵体并进来 |
| 行周边亮部中位数 ≥225 才算文字 | 并框伸进蓝色零件面，暗色碎片把框重新撑到 1502 px |

**字号按行高中位数（×0.9~1.0），不按框高**：两行标注框高翻倍，按框高取字大一倍（实测「顶部注油孔」）。
锚点按原标注对齐方式给（left/right/center），右侧带引线的标注用 `right`，中文短于英文时不留空洞。

## 17. 件号气泡（callout）：判读对账 + 原位统一重绘（`bubbles.py`）

件号气泡（01~28、ST02、T01…）是装配指引的核心信息。原图 85 dpi 时 "09" 像 "C9"、"08" 像 "0D"，
用户明确要求「结合上下文重新整理、规范编号，存疑务必标注」。**照抄超分结果不算处置。**

### 17.1 判读对账（内容层）

1. `bubbles.sheet()` 把每个气泡单独放大成 150 px 格子拼贴（实测 89 个 = 3 张），逐格核读；
2. 与**步骤文字**对账：步骤 2.2 提到 26、09 ⇒ 该图气泡只能是 26、09；与**零件表**对账：件号必在 01~28 /
   ST01~ST11 / T01~T02 闭集内；爆炸图另按局部详图的**零件颜色编码与装配顺序**复核
   （黄=阻尼环 06、紫=隔套 07、蓝=端部轴承 05、橙=中间轴承 08、青=波形弹簧 26）；
3. 结果落盘 `BUBBLES = {stem: {框号: "09"}}`，坐标仍来自检测框，不手估；
4. 判读依据与存疑逐条写进附录 A 乙（哪几幅、哪些件号、按什么核对、若与 CAD 不符以 CAD 为准），
   图下加一行注「件号气泡已按零件表与局部详图核对后重新排版，判读依据见附录 A 乙」。

### 17.2 原位重绘（`bubbles.redraw`）

```
几何三法取最优（fit_quality：环路径墨迹高、环外 +5 px 圈暗采样少）
  ① 填洞法：环是闭合暗线 → binary_fill_holes − 暗像素 = 内腔 → 含编号框的内腔 bbox = 内椭圆（首选，与引线相连无关）
  ② 射线法：72 条射线自编号框边界起算，椭圆模型验证 ≥75% 射线残差 ≤15%
  ③ 模板搜索：同图同规格气泡的半径 + 环路径墨迹密度搜索环心（受限 Hough），图边缘/紧贴虚线框的气泡用
擦旧环：每 5° 实测外沿 +2 px 多边形 ∪ 拟合椭圆 +3 px（偏心/毛边全盖住）
补引线：环外 +7/+12 px 两圈同时为暗的角簇 = 引线方向，补画 rout−1 → rout+5 的短截
新环 + 编号：环厚 = 四向扫描取最小并封顶 0.3×内半径；Arial Bold，字高 0.55 × 内径，宽不超内宽 0.86
```

四条实测坑（避坑 108~110）：

- **椭圆气泡**（ST01/T01）的射线必须从**编号框边界**起算：竖向内半径小于半对角线，从半对角线起算
  竖向射线跳过环、抓到远处物体，环画成竖长椭圆；
- **环厚四向取最小**：只扫一个方向时引线把厚度拉到 40 px，"03" 画成实心黑盘；
- **编号框可能是整个气泡连引线**（T01 的框 112 px 宽），框中心比环心偏右 15 px；填洞法的尺寸判据
  要同时放行「内腔比框大」（框只含数字）与「内腔比框小」（框含整个气泡）两种；
- **相邻气泡**（25 与 26 上下相贴）会互相落进对方的残留判据圈 —— 扣除同图其它气泡椭圆内的点。

### 17.3 旧环残留判据（`bubbles.residue_check`，避坑 111）

用户目测报回：「原部件序号还有保留」—— 新环与旧环没对齐，旧环露出一截 `(T01`。
**全套闸门一处不报**：残留英文关扫的是文本层，那是像素。⇒ 判据：新环外 +4 与 +8 px 两圈采样，
扣除引线角簇（±12°）与相邻气泡椭圆内的点，**连续 ≥3 个采样角（≥15°）的暗弧**即残留
（引线穿过只占 1~2 个角）。首版 89 个气泡查出 5 处：3 处相邻气泡误报、2 处引线未识别，
判据修正后全部归零；用户点名的是 2 处，修的是全书 89 处的判据。
