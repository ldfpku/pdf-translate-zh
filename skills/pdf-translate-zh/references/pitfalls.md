## 一、提取与几何

**①  纯白画布矩形** — Word/Visio 导出的 PDF 里有 `fill=(1,1,1)` 且无可见描边的
巨型矩形，肉眼不可见，却会把整页图元连成一片。
→ 判据：`fill` 近白 且（`color` 为空 或 近白）即丢弃。

**②  右边距修订变更条** — 细长竖线（宽 < 3.5pt、高 > 12pt、x > 版心右边界），
会把插图裁切框上沿拉到正文段落里去。
→ 单独识别、单独还原；因译文行长不同，按**版心内相对位置等比映射**。

**③ ⚠ `find_tables()` 伪表** — 插图中的矩形线框常被误判为表格，
该区域的矢量图元随即被当作「表格线」剔除，**整幅插图静默消失**。
→ 加填充率判据：有效单元格 < 4 或 填充率 < 15% 判为非表。
→ 更彻底的办法：**别用 `find_tables()`**，按线框几何自求（见 `tables.md`）。

**④  零面积线段逃逸** — 表格单元格分隔线是零面积矩形，
用 `(r & tb).area > 0.7 * r.area` 判「是否在表内」**永远为假**。
→ 改用「含于」判断（带 2pt 容差）。

**⑤ ⚠ 循环变量遮蔽** — 页循环内部又写 `for i in range(...)` 会覆盖外层页序号，
之后 `insert_pdf(doc, from_page=i, …)` 取到**错误页面**，产出「图张冠李戴」——
且尺寸完全正常，contact sheet 上极易看漏。
→ 内层循环一律用 `k/idx`；页序号变量起名 `PAGE_IDX` 这类不会被随手复用的名字。

**⑥  堆叠分数被拆散** — 原版 `4 ½` 在文本层是 `4 1⁄ … 2`，分母漂到串尾。
→ 「分数标记之后的第一个孤立数字即分母」，重组为 `4-1/2`。

**⑫  JSON 里带前导空格的键** — 从 PDF 抓的名称常含前导/多重空格，查字典必然 miss。
→ 建映射时统一 `" ".join(s.split())`。

**⑲  零面积矩形** — `Rect.intersects()` / `get_area()` 对零宽或零高矩形恒为
False / 0。描边线常常正是零宽矩形，用 intersects 做版心过滤会把它们整条丢掉。
→ 用纯坐标比较 `r.x1 > L and r.x0 < R and r.y1 > T and r.y0 < B`。

**㉙ ⚠ 退化路径整条丢线** — CorelDRAW 导出的直线常写成 `l` + 若干 `c`
（控制点共线的贝塞尔）。逐 item 取只得到几个零长小段，`_coalesce` 也接不起来。
实测 手册 E 第 6 页零件表的 **5 条列线整条丢掉**，表格一个行带都定不出。
→ 判据：**路径 bbox 若在某方向退化成 0 宽，它本身就是那条线**。

## 二、插图剪裁（从零重建路线）

**⑬  图内标注也可能用正文字号** — 表单类插图的零件名常用 12pt，
按「字号 ≥ 正文即为分界」会把插图**从中腰斩**。
→ 真判据是**几何**：该文本行上下 60pt 内是否都有与其横向重叠的图元。

**⑭  剪裁流程的顺序** — 必须「**先修边 → 再拼接 → 复修边**」。
先拼接时簇框里还含着上方正文残留，会让「合并后不吞文本」的判据永远失败。

**⑯  发丝线要自适应分辨率** — 0.12pt 级线宽按 300dpi 渲染不足 1 像素，
被抗锯齿糊成浅灰。→ 图宽 ≥250pt 用 300dpi、120~250pt 用 450dpi、<120pt 用 600dpi。

**⑰  图与其下方名称的间距** — < 3pt 时名称会压掉图的下沿线条。→ 固定留 5pt。

**⑱  页边「修订变更条」的 x 阈值** — 表格右边框就贴在版心右界上
（实测 x=539.9 vs 版心 540）。阈值取 x>522 会把**每张表的右边框**都当成变更条 ——
实测误检 981 条、真值仅 22 条。
→ 阈值必须**严格位于版心右界之外**。
→ 更要紧的是：**变更条本身不该复现** —— 它逐行标注被修订的英文原文，
译文行长完全不同，怎么摆都落在与内容无关的位置。改在勘误里说明。

**㉖  最下一排图内标注会被裁掉** — 要求「上下都有图元」时，
最下一排零件名（其下方本就没有图形）必然落选。
→ 判据改为三条同时成立：非图题、左边界不落在正文左界上、上方近处有横向重叠的图元；
且「上方」的下界要取到**文本行底部**。

**㉗  空白文本行会毁掉裁切下界** — 名称之上常还有一条**空白文本行**，
其上沿正穿过图形中部。用 `min(y0)` 定下界会切掉图形下部最多 18pt。
→ 只认 `txt.strip()` 非空的行。

**㉘  同一个坑会犯第二次** — ⑤ 犯了两次。
→ 凡「靠肉眼才能发现」的缺陷，都要补一条**机器判据**，否则必然复发。

## 三、图内文字

**⑮  叠印中文要两趟画** — 逐条「画底衬→写字」时，下一条的白色底衬会盖掉
上一条的字脚。→ 先铺完所有底衬，再统一写字；行距 1.22 em，底衬上下各留 0.22 em。

**⑳  同一标注叠印多份** — 原版常把一条标注按不同字号叠印 2~5 份
（实测同一条 7.92pt + 9.55pt 各一份）。英文完全重合、肉眼无异常；
换成中文后宽度不同，立刻露出双重影。
→ 判重键为「文本相同 + 位置相差 < 3pt」，保留字号最大的一份。
**别按纯文本去重** —— 一幅图里「扭矩套」本就会出现多处。

**㉑  位图内烧死的英文** — 矢量英文能 redaction，位图里的抹不掉也提取不到，
**首版必然漏译且自检查不出来**（文本层里根本没有它）。
→ 系统排查法：「有大位图 且 该区域文本层词数 = 0」的页拼成缩览，一次目检即可穷尽。

**㉚ ⚠ 图内位图必须拿源 PDF 量墨迹框** — 成品页上已铺白底写了中文，
再去量「深像素包围盒」量到的是**中文自己**，框越量越小。
实测第二轮重量后 48 条标注的框全缩成 2~4pt，整页作废。

**㉛  带黑边框的标注，粗框要先内缩** — 不缩会把框线包进包围盒，
铺底时连框一起盖掉，图上凭空少一个方框。

**㉜  竖排标注要给转角** — 不给就横着写、直接出框。

**㉝  粗框宁大勿小，但不能碰插图** — 小了留 `ng`／`Be`／`(DIVE` 这类词尾词首残片
（实测 5 处）；大了包围盒被图元拉开。肉眼从缩图读坐标**常差 40pt**，
拿不准就用 `raster_runs()` 在小区域实测。

## 四、叠印路线的提取层

**㉞  `join_wrapped` 把右括号当成句末** — 注意框里以 `… (Bit box)` 收尾的行
拼不回下一行，一句话被切成两条各自翻译，读起来断在半句。
→ 只有句末点号类字符（可后跟一个右括号）才算结束；
并加防误判：**短串**（< 40 字符）以右括号收尾的是**堆叠表头格**（`(mm)` / `(inch)`），不拼。

**㉟  两端对齐的正文被切成逐词单元** — justified 词距实测 8.0~8.4pt，
超过固定的 0.75 em 切段门槛 → 一行被切成 12 个逐词单元，渲染成
「该　拆卸　与　总成　说明…」，一眼机翻。
→ 四条判据同时成立才认「整行是散文」：词数 ≥ 6、词距均匀（最大/**最小** ≤ 1.6）、
词距 ≤ 1.1 em、多数词含小写。（比值除以**中位数**不行 —— 表头行的中位数已被大值拉高。）

**㊱ ⚠ `keep` 规则吞掉的条目既不译也不报** — 它在 lookup 之前跑。
实测 `^[A-Z0-9\-]{2,}$` 把**所有全大写单词**当成代号保留，一次吞掉 **398 条**
（`CUSTOMER`／`RIG`／`LENGTH`／`CHROME`……），而**残留英文自检报 0**。
→ 代号规则必须**要求含至少一个数字**；分数规则必须带**尾锚 `$`**。
→ 写完 `keep` 后 dump 一份「被吞掉的唯一串」人工过一遍。

**㊲  分批词表的重复键：先加载者胜，后写的静默失效** — 实测「改译文无效」，
因为同一键同时在 `b10` 与 `b12` 中。
→ `batchwork.dupes()` 是交付前必跑的一条检查，必须为 0。

**㊳  空串 `""` 意为「保留原文」** — 真要抹掉必须写**单个空格** `" "`。
实测「页脚文档路径要去掉」时踩过。

**㊴ ⚠ 表格格内文本必须从源页取** — 成品页上的文字已被叠印层按行聚组重排过，
相邻两格常已并成一条写进其中一格（实测 `CONSUMABLES`+`PN` → 「零件号 消耗品」
整条落在最右格）。网格是对的，错的是**文本来源**。

**㊵  主列线回补必须分子表统计** — 混在一起统计会把零件表的列线补进消耗品表，
`WRENCH … CATCH RING` 被从中间切成两格。

## 五、写入与版式

**⑦  `sys.stdout = io.TextIOWrapper(...)`** — 该模块被 import 后，
旧 wrapper 被 GC 时会关闭底层 buffer，调用方 `print` 抛
`ValueError: I/O operation on closed file`。
→ 一律用 `sys.stdout.reconfigure(encoding="utf-8", errors="replace")`。

**⑧  块 DSL 的可选参数位置** — `("ol", items, mode)` 与
`("ol_from", start, items, mode)` 的 mode 下标不同；写成统一的 `b[3]`
会让所有 `alpha` 静默退化成数字序号。

**⑨  表格里的裸字符串** — ReportLab 对未包 `Paragraph` 的裸串用默认西文字体，
中文渲染成 ■■■。→ 所有单元格一律过 `Paragraph`。

**⑩  填写栏下划线** — 全角 `＿` 之间会断开，半角 `_` 在部分中文字体里也不连。
→ 用 `<u>　　　　</u>`（带下划线的全角空格）。

**⑪  删文件的通配符** — `Remove-Item figures\*.png` 会连同专用剪裁产物一起删掉。
→ 用 `fig_*.png` 精确匹配。

**⚠ 静默丢字** — `insert_textbox` 放不下时**一字不写、也不报错**，只返回负值。
实测某页 116 段只落了 46 段，丢的全是较长的字段名。
→ 宽**与高**都要收敛；度量必须与 `insert_textbox` **同源**
（`fitz.Font(fontfile=…).text_length`，不能用 reportlab 的 `stringWidth`）。
→ 「先量后画，只画一次」；`rc < 0` 重画不会叠残迹（已三组对照实验证清）。

**㊶  `insert_textbox` 不会在中文里断行** — 只在空格处断。中文长串被当成一个词，
放不下就整块挪到下一行，首行只排三分之一。
→ 自己按中文禁则**预折行**（`_cjkwrap`）。**旋转单元不折**。

**㊷ ⚠ 旋转单元不能做 y 方向的任何手脚** — 让位、借空白、同行字号取齐、预折行
都只动 y 方向；对 `rotate=` 的单元，y 正是**行长**方向。
实测 手册 B 第 43 页拆卸汇总表 21 条零件名被推到页面外，页上只剩 4 条完整、
4 条被左边界切掉 —— **六道关一处都没报**。

**㊸  右对齐判据要看墨迹，不看写入框** — 行级通道会把写入框放宽到单元格右边界，
同一格里每条都天然齐平。实测 手册 A 第 9 页消耗品清单的 3 条项目符号 +
4 个表头标签被判成同一「右对齐列」，整片文字贴到中缝上。

**㊹  `LINE_ART_REMOVE_IF_COVERED` 要豁免文字** — 抹除带正压在刚写好的中文标题上，
不加 `text=PDF_REDACT_TEXT_NONE` 就把标题一起抹了。

**㊺  中文判据要含全角标点** — `[一-鿿]` 不含 `。`(U+3002)，
`MSDS。` 这类整句译文的尾巴单独成行时会被误判为残留英文。
→ `[一-鿿　-〿＀-￯]`。

**㊻  词表值里不许出现 Markdown 星号** — `**切勿**` 会原样印进 PDF（实测 8 处）。
叠印路线没有内联粗体，星号一律去掉；ReportLab 路线改 `<b>…</b>`。
交付前扫 `\*\*[^*\n]{1,20}\*\*`，注意排除**原文自带**的脚注星号。

## 六、装配与页码

**㉒  版心下边距必须高于页脚最上沿** — 页脚分隔线在 y=60 时，下边距若仍取 56，
正文就压在页脚上。→ 下边距 ≥ 页脚顶 + 8pt，并加自动核验。

**㉓  逐页装配自检必须「实排」，不能「估高」** — 用 `flowable.wrap()` 累加估高，
对「单元格内嵌套 flowable 的表格」估不准，会漏检溢出。
→ 每个逻辑页**单独排一次**，实测页数必须为 1。这是唯一可靠的判据。

**㉔ ⚠ 逻辑页溢出是隐形杀手** — 1:1 同源版式下任一逻辑页多排一页，
其后所有页的页眉页脚标签整体错位 —— **页码看着仍然连续**，只是内容与页码对不上。
→ 除 ㉓ 外，构建期加硬闸门（断言附录起始物理页号），并做「目录 ↔ 实际页面」交叉回验。

**㉕  多页附录不能预估页数** — 预估与实排差 1 页就会让附录之后所有标签错位。
→ 两趟构建：先排一遍读出真实起止页，再带正确标签重排。
找边界的标记词要选正文/封面绝不会出现的串 —— 封面若写有「见附录 A」，
用「附录 A」当标记就会命中封面。

**㊼  目录跳转链接必须在合并附录之后加** — 附录一并进来物理页号全变，链接全废。

## 七、工具层

**㊽  heredoc / shell 会吞掉字面反斜杠** — `\\n` / `\\x01` 写进 heredoc
会变成真的控制字符，把源码文件写坏（实测毁过 `hybrid_overlay.py` 与一个词表模块）。
→ 生成代码时一律用 `chr(10)` / `chr(92)` / `repr()`，**别在 heredoc 里出现字面反斜杠**。

**并发构建的字体缓存竞争** — `rebuild_all` 并行跑时偶发一次性失败，
单独重跑即通过。判据：同一脚本单跑 PASS、批量跑 ERR 且无 FAIL 明细 → 是竞争，不是缺陷。

## 七之二、封面与目录（详见 `cover.md`、`toc-and-nav.md`）

这一组的共同点：**六道关一处都不报**。链接是注记不进文本层，对齐是坐标不是内容。

**㊿ ⚠ `centered_units` 只认单行 → 多行居中标题块被排成左对齐。**
封面的副标题堆叠正是多行居中块（`6-3/4" Motor with "R" Bearing` / `& ALPHA Claw`
在提取层里是**一个**多行单元）。以「多行段落也可能恰好居中」为由一律否掉，
中文就按左对齐落进原框 —— 主标题居中、副标题左对齐参差。**实测五册封面全中。**
⇒ 行数不是判据，**墨迹**才是：居中块各行中线取齐而左右不齐，两端对齐段落
则左右都齐（故居中判据要求中线离散**严格小于**左右离散）。

**51 ⚠ 对齐判据的容差必须相对块宽。**
写死几 pt 会因字号不同带来的字边距差失手 —— 实测 手册 B 源封面标题块中线离散
**2.6pt**，绝对容差取 2.5 就差 0.1pt 把「明明居中」判成无定形，
判据自己变哑、成品歪着也报绿。⇒ `lim = max(2.5, 0.03 × 块宽)`。
同理，**比对源与成品要用同一把尺**（取源块宽算容差）：中文更紧凑 ⇒ 成品块更窄
⇒ 容差更小 ⇒ 同样的物理离散在成品这边反而判不过，判据会因为「译得好」而报错。

**52 ⚠ `toclinks.add` 不幂等。**
装配用 `saveIncr` 增量写，重跑一次就再叠一层链接。`set_toc` 会整体替换书签，
故**链接数 = 书签数 × 2 就是这个毛病的指纹**（实测「134 链接 / 67 书签」）。
⇒ 加链接前先清掉本页已有的 `LINK_GOTO`。

**53 ⚠ `reflow.LINKS` 每次 `render()` 开头清空。**
多区域目录（双栏、跨页）由 `run()` 逐区域调用 ⇒ 前面区域的链接被后面冲掉。
实测双栏目录 52 条只建出 **13** 条。⇒ 取 `reflow.ALL_LINKS`。

**54 原版目录的页码可能是错的**（未刷新的 Word 域）。实测 4 条：三条各差 1 页、
一条分节页码错一级。照抄就把跳转落到前一页。⇒ `toclinks.add(..., fix={...})`，
逐条记入附录 A 甲。只有「落点回验」查得出来。

**55 目录与正文译名不一致。** 实测 4 条（`Jar Latch` 目录作「震击器闭锁机构」、
正文作「闭锁机构」等）。**页码都没错** —— 错的是读者按目录检索不到。
⇒ 改目录去就正文（正文出现次数多，动它风险大）。

**56 ⚠ 文件编号索引不能按整页文本做子串匹配。**
有的手册由若干分册装订而成，目录右列是**文件编号**而非页码。若拿
「整页文本含该编号」定位，会错两次：短码互相包含（`ASSY` 命中每一个
`DISASSY` 页）；正文里的交叉引用（零件表提到 `IC7011`）抢在真正的分册首页之前。
实测让 4 册各错 3~4 条落点。⇒ **只认页眉带、且要求那一行以编号开头。**

**57 链接矩形不能照抄行框。** 行框含升部降部，实测高 11.5 而行距只有 10.85 ——
相邻两条压叠 0.7pt，点上一条可能跳到下一条。⇒ 纵向内缩 0.6pt。

**58 ⚠ 抹除框 ≠ 写入起点，且只有完全落在框内的路径才会被删。**
原版最左的一列文字往往比正文起排位置更靠左：**抹除框**要盖住它（收窄了原版
那列英文就露出来），**写入起点**才是译文实际起排的 x。写窄抹宽不留残影，
反过来必定漏抹。另外矢量线的删除判据是「完全包含」不是「相交」——
实测旧表格左边框在 x=256、正文在 266，抹除框从 266 起就**一条旧网格线都删不掉**，
成品上新表左侧横穿一堆旧线。⇒ 重排前先量该区域全部图元的最左边界。

**59 判据自己造假阳，比没有判据更糟。**
人会学会无视一个总在叫的判据。本项目为此改了六处误报（详见 `toc-and-nav.md` §7）：
条目数不能拿链接数充数、抽不出关键词就别报、条目文字要取「行中心落在矩形内」
的那一行、按索引键分流验法、双栏要先聚类再判齐、比对前去空白并剥尾随标点。
真要留着不修的，**写明理由**（`tocsweep.WAIVE`），且只豁免精确匹配到的那一条。

## 七之三、表格里的记号与上下标（详见 `tables.md` §9.1、§9.2）

**60 ⚠ `wordWrap="CJK"` 让任意两字符之间都可断，工程记号会被劈开。**
`2020-08-17` → `2020-08-1` / `7`（断行处还顶穿行高、压住表格线）；
`0.005"~0.009"` 从引号中间断；`ASTM E384` → `ASTM E3` / `84`。
而实测那张表右侧连同版心两侧**都空着一大片** ——
**不是没地方，是列宽求解时没把记号宽度算进去。**
⇒ 分列前逐列求「最宽原子记号 + 内边距」作**硬下限**，富余再按原比例分回
（`render.fit_cols`／`reflow._atom_floor`）。
⚠ 记号正则的择一是**最左最先匹配**，长模式必须排前面：千分位排在
「数值+单位」前，`10,000 psi` 就只认到 `10,000`。

**61 ⚠ ReportLab 的上下标只改字号与基线偏移，`leading` 纹丝不动。**
`<sub>` 默认 rise = **−0.5 em**（老默认，惯例约 −0.2 em）、size = 0.8 em。
实测 7.4pt/9.6pt 的表格样式：下标探到基线下 4.94pt，而到次行字顶只剩
3.1pt —— **压进去 1.8pt**，下标贴死在下一行字头上。
⇒ **压浅下沉量 + 补行距，缺一不可**（只压浅仍会蹭到，只加行距则行高白涨）。
⚠ `rise=` 是**增量**不是绝对值、单位是 **pt**、默认值按**母字号**算 ——
故改写必须在知道实际字号的地方做（`render.P`），不能留给内容层。
⚠ 标点不要包进标签：`HV<sub>0.3 kgf</sub>。` 才对，写成
`HV<sub>0.3 kgf。</sub>` 会把句号一并缩小压低。

## 七之四、固定格式注记块（详见 `text-layout.md` §10）

**62 ⚠ 样板注记块的换行是物理的，不是语义的 —— 叠印必然割裂语义。**
`FINISH: 125∨ MAX.; 63∨ ON ALL / THREADS & RELIEF SURFACES.` 是一句话，
被行边界切成两个待译单元各自成句译出；末句同理，且第二截为塞进原行框
被**缩到极小、挤压变形**。同一块里还有两个共犯：**列对齐靠前导空格**
（`keyclean` 一归一空白就全丢）、**`±`/`°`/`∨` 是矢量不在文本层**
（译文补 `±` 就与原矢量重影，不补则整列没有）。
⇒ 整格抹掉重排，用 `("cols", …)` 定列块（偏移以 em 计随字号缩放），
`±`/`°`/`′` 改用真文字。实测 图纸族 J 四张图 12 页一次全中。

**63 ⚠ 在成品页上解析源版结构 = 静默失败。**
`dwgnote.parse()` 认的是 `UNLESS OTHERWISE SPECIFIED` 这类**英文锚点**，
而成品页上早已换成中文 —— 返回「本页无此块」且**不报错**，看着像跳过。
⇒ 凡「按原版结构做的解析」，一律双页签名 `fix(page, src_page)`，
装配流程必须传源页。同族的还有 ㉚（图内位图必须拿源 PDF 量墨迹框）。
⚠ 配套两条：**同一份样板各图取值不同**（0019 是 `.X ±.040`、0032 是
`±.030`、角度 `0.5°`），写死会把甲图公差印到乙图上而六道关不报；
**区分大小字要用字号不用行高**（3.9pt 与 5.9pt 的行高是 5.47 与 5.9，
阈值取 5.4 就差 0.07pt 失手）。

## 七之五、裁图与图内标注（详见 `figures.md` §9、§10）

**64 ⚠ 位图 bbox ≠ 图的视觉范围。**
带引线标注的图，标签与引线常是页面上**独立的**文本/矢量对象，
画在 `get_image_info()` 的 bbox **之外**。直接按 bbox 裁：标注被腰斩
（留断头引线、半个字的残影）或反过来蹭到相邻正文（图上方露出一截
无关英文）。两类都实测踩过。⇒ 用 `figcrop.safe_extent()`。

**65 ⚠ 判据的统计范围必须局部化，且必须有硬上限。**
求「正文基准字号」时若按**整页**统计，同页只要有一张密集参数表
（十几行 5.5pt 数字）就能在数量上反超几行真正文，5.5pt 被当成基准，
于是真正 9pt 的正文整页被当成「图内标注」，裁框膨胀到原图 **11 倍**。
同理不能按**字符数**加权——表格单元格字符多、每格却只三五个字符。
⇒ 统计范围限定在该图周边窗口；并设 `max_area_ratio` 硬上限，超了就
**退回原始 bbox 并报警**。**不设上限的判据，错起来比没判据还离谱。**

**66 ⚠ 求范围要「从图心向外逐个吸附」，不能一次性求并集。**
一次性并集时，任何一个被误判的远处候选都会把裁框一次性拉穿整页，
且事后无从分辨是哪一个（实测把邻栏整张表格 + 小节标题全吃了进去）。
逐个吸附则天然有序：按距离从近到远，一旦间距超过阈值就**直接停手**。

**67 ⚠ 回叠坐标必须与裁框同源，绝不手估像素框。**
手估坐标与实际裁框来自两次独立判断，裁框哪怕微调 2pt，全部标签就
整体错位。⇒ 裁图时把检测出的 `hits` 换算成裁图内像素坐标落盘，
回叠时直接读。另：跑序必须 `crop → translate`（裁图会覆盖 png、
抹掉上一轮叠的中文——这是**有意为之**，避免反复叠字重影）。

**68 ⚠ 图题排除要按块不按行，外框线还要设禁区。**
只排除 `startswith("Figure")` 的**行**，图题折行后的续行
（"Joint, & Flexshaft"）照样被当成标注吸进裁框——成品图里残留半截
英文图题。⇒ 块首行命中图题模式 ⇒ 整块是图题；紧贴其下、横向重叠的
块按续行传染。图题文字排掉后，其**外框线**离位图常只有几 pt，
pad 一加又裁进来一条黑杠 ⇒ 图题元素（文字或与其相交的矢量框）进入
裁框边缘带时，按方位把对应边钳回，且钳位 margin 必须大于 pad。

**69 ⚠ 「矢量标注 = 0 才查位图英文」会被一条矢量图题击穿。**
（㉑ 的排查法就此作废）一幅图只要检出任何一条矢量文本——哪怕只是
图题折行的残行——就躲过位图排查。实测三联对照图：1 条矢量图题 +
13 条位图标签整幅漏译，直到用户点名。⇒ `figlabel.sweep()` **逐幅全查**：
检测全部文字块，减去已处置区域，余下描红人工确认；合法保留录
白名单并注明内容，复跑到 0（见 figures.md §11）。

**70 ⚠ 空译名 ≠ 未收录：判断用 `is None`，不能用真值。**
空串译名的语义是「只描白不写字」（该行语义已并入相邻行，如
Housing 并入传动壳体）。用 `if not zh` 判 miss，空串条目全被静默
跳过——计划抹白的英文残段原样留在成品图里，且自检不报
（条目明明写在表里，谁想到会被真值过滤）。

**71 ⚠ 图的尺寸权重是内容的一部分。**
原版独占一页的整机总览图被排成 90pt 宽小图——信息没丢，出版人赋予
它的视觉权重丢了（用户点名退回）。⇒ 输出宽 ≥ 源版物理宽（含标注的
ext 宽），占页图仍占页。图题**不入图宽列**：跟随图宽必然把窄图的
图题折成两行，图题宽度应取版心宽（figures.md §12）。

**72 ⚠ 裁框规则变更后，一切基于旧裁图的像素坐标即刻作废。**
图题改为裁剪阶段排除后裁图变矮：遗留的旧「图题描白区」压到真图形上
（差点抹掉总览图的钻头下端）；ext 尺寸跨过 dpi 档位阈值（250pt）时
整图坐标系换算。⇒ 重裁之后：过时描白条目清理、RASTER 坐标逐幅与
新裁图核对——sweep 核查图上的蓝框正是干这个的。

**73 ⚠ 图题配对不能按阅读顺序捡漏——必须从源版几何取真值。**
抽取器把 [FIG] 占位放在页首、图题却在阅读流位置，重排后「就近配对」
一处错配即全章级联（实测 图4.0 配错 → 4.1~4.5 全部串位，用户点名才
发现）。⇒ 从源版提取「图题行 ↔ 同页图（y 邻接）」的真值映射，把配对
显式写进内容层（figc 块），装配层零启发式。用户报一处，先跑全书
图题-图数对账，再动手。

**74 ⚠ 图清单三源并集：嵌入位图判据抓不到纯矢量图表。**
按「嵌入位图 bbox」建图清单，纯矢量图表（性能曲线、温度折减图）
必然漏掉（实测一册漏两张，其一靠翻译代理留下的描述性注记才追回）。
且「全书文本是矢量」不保证图内标签是矢量——同册中示例曲线的标签
烧死在位图、规格曲线的标签却在文本层。⇒ 图清单 = 嵌入位图 ∪
高路径密度区 ∪ **图题行反查**（有 Figure N.M 行而无图者即漏网）；
每图按「区域内文本层有无标签」分路处置，不能按全书一刀切。

**75 ⚠ ReportLab 模板切换的三个撕页坑。**
① `NextPageTemplate` 在**下一次断页**才生效：[PageBreak, NPT, PageBreak]
会先撕出一张空白页——NPT 必须紧贴它要进入的那次 PageBreak **之前**；
② 整页图占满 frame 后，其后的零高 flowable（Marker 探针）溢出到
**下一页**——章标记必须放在整页图**之前**；
③ 连续整页图之间残留的 [NPT(body), PB] 对同样撕空页。
⇒ 构建收尾统一跑一遍 collapse 扫描 + 「空白页 = 0」常驻判据
（无文本且无图即空白）。

**76 ⚠ 浅字深底表头是暗字检测的第二盲区，且 sweep 不报。**
检测判据认「深色、细小、成行」——绿带/蓝带上的白字表头是亮色，
整批漏检；sweep 也过（那里确实没有未处置的**深色**文字块）。
实测一册 6 张烧死表格的表头全部静默漏译。⇒ 表头按**底色连通域**
定位单元格（`figlabel.band_cells`），整格重绘 + 白字中文
（`figlabel.repaint_cell`）；只重绘有译名的格，数值/单位格原样。

**77b ⚠ 纯白贴片是块白斑：底色必须采样，不能写死 (255,255,255)。**
灰色图面上贴纯白 = 刺眼白斑（实测「转子」贴在浅灰转子面正中）；
JPEG 纸面也不是纯白（≈250 灰），纯白补丁四边显边界；固定 grow=2
盖不住压缩蚊噪与原英文的抗锯齿残晕，标签四周留「幽灵残影」。
⇒ `figlabel.bg_color()`：采样贴片区（含外扩）的**亮部中位色**作底
（深色墨迹先剔除）——转子面得灰、纸面得米白，贴片隐形；文字颜色按
底色亮度自动黑/白；grow 提到 ≥6 吞掉噪晕。

**77 ⚠ 回叠描白框不收紧 = 遮图；字号随框走 = 忽大忽小。**
检测框常把星形轮廓、十字线、相邻行并进来——整框描白会把图形抹掉
一块；`_fit` 「能放多大放多大」使中文随框虚高，同图字号乱成一团
（用户点名：「转子」大白框盖掉剖面中心、译字放大数倍）。
⇒ `apply_raster(smart=True)`：① 描白前 `tighten_box` 把框收紧到真实
文字行（框内二次严检；仍收不动的按同图基准字高选**最近中心单候选**，
求并集会被漏网碎片重新撑大）；② `uniform_size` 同图字号统一
（单行框高中位数 × 0.88），超宽才降号——「同行字号向下取齐」的图内版。
⚠ 人工特设框（多行联合覆盖、漏检补框）**豁免收紧**（收紧会只剩一行、
露出其余英文），走 `smart=False, uniform_px=共享字号`。
病理框两轮收不中就画网格实测，不猜第三轮。

**78 ⚠ 管线上游改形态后，下游可能在「空转 + 叠涂」而一切看似正常。**
图题真值布线把裸 fig 块转成 figc 后，裁图脚本的图清单源（fig 块）悄悄
变空：「共 0 幅」照常退出 0、还把清单文件**空覆写**——此后每轮
「重裁→回叠」实为**在已回叠图上叠涂**，新旧涂层互相遮掩，修复效果
的目检结论全部失真；清单一空，矢量回叠也静默跳过。
⇒ 三道保险：① 管线各环节的「处理了 0 个」一律**当错误报警**，不许
静默成功；② 清单/落盘文件更新用**合并**不用整体覆写；③ 产物文件名
含内容标识（页号+y）时，重建路径上把标识**锚定**住——上游取整方式
一变（550→549），全部引用即刻错位。

**79 ⚠ 图文自然顺序不可倒置；堆叠公式平文字化 = 歧义。**
① 语义重排以「块」为单位，但**文本→插图→文本的源版顺序是内容的
一部分**——未配图题的插图按锚点补位时，锚点必须取源版阅读顺序的
邻接块（实测公式段插图被补到公式块之后，读者先见公式后见图）。
② 堆叠分数的**分数线覆盖范围就是括号**：文本层平化提取后括号语义
丢失（"(A+B)/2 − C" 平成 "A + B − C / 2" 谁除谁全乱）。处置：能从
上下文闭环勘定的（如 正配合=压缩 ⇒ 配合值=转子平均径−定子小径），
按显式括号重排进正文并入附录甲；不能闭环的保留原式+附录乙存疑。
图内说明性公式与正文公式重复时，移入正文排版、图内平化条目抹除
——图里排不出分数线，正文排得出。（⑥ 的公式版；细节 formulas.md）

**80 ⚠ 浮动元素（图/表）的楼层要与源版对账，含 tbl 标题。**
代理输出的浮动块位置不可靠（实测 图6.1 挂到 6.2.4 下、表6.0 挂到
6.2.6 下、图4.1 挂到 4.2 下——用户点名一处，机器对账查出三处）。
⇒ 真值 = 源版几何：每条图表题在源版阅读序中的**前导小节号**；译稿中
该元素的前导 h2/h3 编号必须一致，不一致整组搬到正确小节末尾。
三个实测子坑：① 表题常在 tbl 块的 title 字段里，只扫 note/p 会漏；
② 搬迁组**不得并入自带图题身份的邻块**——否则 A 搬家拖着 B 走、
下一轮又把 B 搬回来，永不收敛；③ 该对账要做成**常驻闸门**
（图题-图数逐条清单），交付前必跑。

**81 ⚠ 烧死表格一律绘制重建；窄列数字三禁；竖向 SPAN 阻断分页。**
审定绘制规范：字体一致、数字右对齐、保留千分号、裸小数补前导 0
（.028″→0.028″）、文本列不加粗、表头蓝底白字常规字重、跨列组头
SPAN 合并、组标签列竖向 SPAN 合并。数字单元格三禁：禁 CJK 断行、
禁 splitLongWords 词内断、只允许显式 <br/>（区间在连字符后折：
0.39°– ↵ 1.0°；0-60/30 在斜杠后折）。矢量源表格**禁止让代理平文本
转录**（实测行列错位、整列空缺），一律脚本按源页几何抽取。
⚠ 竖向 SPAN 会阻断 Table 跨页拆分——长表（17 行故障排查）带竖向
合并直接 LayoutError，组合并只用于确定单页的重建表。

**82 ⚠ 管线映射的「复活」：下游升级后，上游映射必须同步降级。**
图题→图 布线映射（CAPFIG）把图题 note 转成 figc；后来某图升级为
真表格重建、figc 删除——重跑布线时映射还在，把图题**又转回图片**，
成品真表与旧截图并存。⇒ 元素处置形态变更时，其在所有映射表里的
条目同步改写（figc→None）；管线每一环都要经得起重复执行（幂等），
「重跑一次多一层」类缺陷（本条与避坑 52 链接幂等同源）。
伴生两条：孤行页判据（页文本 ≤60 字符且无图 = 孤行页）进常驻闸门；
正文样式常开 allowWidows=0/allowOrphans=0。

## 七之六、幻灯片／演示文稿（详见 `slides.md`）

来自 79 页某客户培训讲义整册交付。这一族的共同点：**四道关全绿**，
毛病全在「单元切错了」或「位置对不对」。

**83 ⚠ PUA 归一必须做在「导键与装配共用的那个 `norm()`」里。**
只在 `keyclean` 内部归一是不够的 —— 内容层自己写 `" ".join(s.split())`
当归一函数时，PUA 原样进了键。实测 `3° per 100'` 的度符是 U+F0B0：
词表里写普通 `°` 永远 miss，而未命中报告只说「有一条没命中」，
不说为什么。⇒ `keyclean.norm_pua()` 现在会把**残留码位**记进 `PUA_LEFT`
由闸门报出来，不许静默（雅黑没有 PUA 字形，漏网的一律渲染成方框）。
⚠ Wingdings 的符号族（U+F0A7/F06E/F075）原表没收，已补。

**84 ⚠ `vectext.snap()` 只许微调，不许塌缩。**
旧实现没有下限：实测一条 51pt 宽的 `Kelly Mandrel` 被吸附到单个笔画连通块
上、只剩 25pt，描白只盖住 `Kell`，右半截英文原样留在成品图里，
**而回叠计数照报成功**。⇒ 新增 `min_frac`（新写的回叠一律传 0.72，
收不足即判失败、退回粗框）。
⚠ 更根本的一条：**粗框若本身就是检测器在源页上按墨迹检出的，就别再吸附**
—— 那已经是精确框，再吸附只会引入位移（实测一条图注被 snap 拉到照片暗底
边上，中文贴在英文**上方**，英文原样留着）。

**85 ⚠ 斜排回叠的两处旋转，符号相反。**
`Point * Matrix` 直接在页坐标（y 向下）里乘，正角即视觉顺时针 ⇒ 描白四边形
用 `+deg`；而 `insert_text(morph=…)` 的矩阵作用在**文本空间**（y 向上）
⇒ 文字用 `−deg`。取同一个符号：要么字往右上排、要么描白框转反了
（英文没抹掉、却在别处啃出缺口）—— 两种都实测见过。
⇒ 用 `vectext.slant()`，别自己拼矩阵。
附带：**描白必须用旋转四边形**，轴对齐矩形会把标注旁边的曲线连带啃掉
一大块 —— 这类标注恰恰就压在曲线上。

**86 ⚠ `check_glyphs` 会把「原版保留下来的符号」报成豆腐块。**
拿整页文本比对雅黑 cmap，叠印路线保留的原版 Wingdings 项目符号（U+F0A7）
一次报出 **41 处全是假阳** —— 它们自带 Wingdings 字体，渲染得好好的。
判据自己造假阳比没有判据更糟（避坑 59）。⇒ 按 span 的**字体名**分流，
只查落在注入的中文字体里的字符（`only_fonts` 参数）。

**87 描白框要吃掉降部与上标。**
框卡在墨迹外沿上会留一小截黑渣（实测图题 `Pipe` 的 p 尾、`1/2` 后的英寸符
各留一处）。⇒ 框宁可上下各多吃 2pt。
但**多行标注的写入框要比描白框再大一圈** —— 两者同宽时多行标注必然溢出
（实测 3 条）：描白只需盖住原英文，写入还要容下行距与升降部。

**88 ⚠ 项目符号有两种形态，只有 `rawdict` 能一视同仁。**
① 自成一行（符号与正文分属两个 line）；② **行内首字符**（同属一个 span）。
按 span 框取正文起点对形态 ② 是错的 —— tx0 落在符号自己身上，抹除框从那里
起算就把符号一并抹掉，**实测整页项目符号消失**。形态 ① 的裸符号行要认领给
右邻同基线那一行，不认领则整页子条目一条都认不出、正文并成一块散文写出去
（溢出图区，还剩下没人认领的裸符号）。

**89 字号/字色取「主导 span」，不取 max。**
行尾常挂一个更大字号的**段落标记空 span**（实测正文 20pt、尾挂 24pt）。
取 max 会让该行与本组「跨字号」不符而接不上，一句话被切成两条。

**90 ⚠ 分组必须先按列聚类，再按纵向邻接。**
沿 y 序贪心吞并会把并排的几条引注串成一条 —— 它们 y 交错、只在 x 上分得开
（实测一页三条照片引注被串成一条 8 行怪串）。

**91 ⚠ 原版字色是内容，不能一律写黑。**
母版正文常不是黑（实测深藏青 `#003366`），小标题另有一色，而作者会用红/绿
标注重点结论（`#00B050` 标了「RARE / LESS COMMON」几条）。写成黑的就把这层
视觉编码抹平了。⚠ 强调色可能只落在折行条目的**第二行**上，按首行取色会
丢掉 ⇒ 一组之内只要出现非正文色，整条取该色。

**92 ⚠ 避头尾补丁打在了错误的绑定上（真 bug，已修）。**
`zhlib._patch_kinsoku()` 只改 `textsplit.ALL_CANNOT_START`，而
`platypus.paragraph` 在**模块加载时**就 `from … import ALL_CANNOT_START`
取走了一份字符串副本，CJK 折行走的正是 `paragraph.cjkFragSplit`。
补丁看着打了、实际没生效 —— 实测照样排出以「，」开头的行，而
`check_line_start()` **报得出来、折行时却拦不住**。⇒ 两个绑定都要改。
同族一条：`hybrid_overlay._NOHEAD` 漏收**中文弯引号与省略号**，
译文里「称为“海滩状纹”的波纹」正会把 `”` 甩到行首。判据与折行用的是
两张表，漏一张就白报。

**93 ⚠ 带项目符号的条目无条件入流。**
按「最左符号 +40pt」筛列表成员，会把第三级条目（缩进比一级深 72pt）踢出
流外，它们随即被当成图内引注居中排、还反过来充当流的右界障碍 ——
**实测整页排成一字竖排**。层级深浅是**缩进**，不是「是不是列表」。

**94 ⚠ 幻灯片的列表必须整列重排，不能逐条钉回原坐标。**
原版条目间距是按**英文占几行**排的：英文两三行的条目译成中文常只剩一行，
逐条回原位就在条目之间留下一个个空洞；反之长条目折行后又压到下一条上
（而未命中/溢出/残留英文/缺字四关全都看不见重叠）。两种毛病同源。
⇒ 整列抹掉重排，间距取原版**中位值**，层级用各自原缩进，排不下时先缩间距
再降字号。
配套：重排后条目上移，原版 Wingdings 字形留在原处就成了孤儿符号 ⇒ 在
**源页**上量出符号墨迹框与颜色，用 `draw_rect` 原样重绘并随正文平移。
另：**向下借空白时必须把其他单元也算作障碍**，只挡图不挡文字，长条目折行
后就压在下一条上。
⚠ 但原版**自带换行**的条目（逐项一行的数值清单）要按原行结构保留换行，
不能并成一段 —— 那是清单不是散文，并起来读者就找不到某一项了。

**95 ⚠ Unicode 下标字符在中文字体里根本不存在。**
微软雅黑、宋体、黑体、等线**全都没有 U+2082**（实测 `has_glyph=0`；
只有 Times/Segoe Symbol 有，但它们没有汉字）。写 `H₂S` 就是豆腐块。
⇒ 走真正的排版下标：把该位数字从文本层抹掉（`add_redact_annot(fill=None)`
只删字形、不铺白块），再按 0.70 倍字号、下沉 0.17 em 重画
（`slidekit.subscript_pass`）。
⚠ 之二：改排后提取层里 `CO2` 会裂成 `CO` + 独立的 `2`，**保留项判据必须能
容纳自己做的这个形态变更** —— 但要逐项确认两截都还在，而不是一句
「豁免 CO2」了事。（先试过「两边都去空白再取 token」，反而在源侧造出
`21/22/2014`、`9.3411/22/2014` 这种跨行假 token，更糟。）

**96 ⚠ `insert_font` 是逐页嵌入的，不子集化会让文件涨几十倍。**
实测 3 页的表格文档从 0.30 MB 涨到 **22.6 MB**（75 倍），79 页讲义涨到
31 MB —— 每页各带一份完整雅黑。图像一个字节没多（比对 `extract_image`
总字节数完全相同），全是字体。
⇒ 存盘前 `doc.subset_fonts()`，再 `save(garbage=4, deflate=True, clean=True)`。
⚠ `saveIncr()` 无法子集化：要另存临时文件再 `os.replace` 覆盖。

**97 逐幅检测器在照片上不可用，在白底线条图上很准 —— 分开用。**
「深色、细小、成行」的连通块判据，在锈蚀/点蚀照片上遍地都是：实测 79 页
一次报出 **2599 处**，几乎全是纹理。补两条判据（框内亮部标准差 ≤30 表示
底色均匀；墨占比 6%~55%）后降到 1771，**仍不可用**。
⇒ 认清能力边界：检测器的角色是**在白底图上给框**（图表、示意图、带框标注
很准），照片上的标注只能靠人看图读字。别让一个总在叫的判据留在流水线里。
⚠ 深底白字是检测盲区（避坑 76 的一般化）：**反相后再跑同一套判据**即可。

**98 断句体检要做成机器判据。**
物理断行若被当成语义边界，会留下「以小写词起头」「以介词/连词结尾」的残条。
这是 V2 公理的机器化 —— 不做这一步，切碎的句子照样能过六道关（字写进去了、
不缺字、不残留英文），**只有读者读到才发现断在半句**。
⇒ `slidekit.orphans()`，交付前必须为 0。

**99 小色块里的标注要显式给底色。**
环带采样（避坑 77b）对**大面积底**有效，但标注若印在一个小色块里
（黄底引注框），环带采到的是框外的锈面，贴出来是块褐斑。
⇒ 这类标注在内容层显式给 `fill`，并收紧外扩免得盖过框边。

**100 ⚠ 裁框不知道英文图题在哪 —— 中文图题正上方留半截英文。**
裁一幅图有三个坐标来源：位图 bbox、矢量簇并集、标注外扩。三者都只描述
「图画到哪里」，**没有一个知道英文图题在哪**。再各加几 pt 余量，裁框就顺势
吃进图题顶端几 pt —— 成品上是一条「Figure 4-7」的上半截横在中文图题正上方。
**全套闸门一处不报**：图题随位图裁进去了，不进文本层，残留英文关扫的是文本层。
实测某册 24 幅插图中 **16 幅**、第 7 节 22 张现场照片中 **12 张**、
另一册 6 幅中 1 幅，同一根因。
⇒ `figclip.clearance()`：裁框 ∩ 源页上未 redaction 的文本 span 必须 = ∅，
   与图题的硬上下界（真值布线）合用；固化为常驻闸门 `checks.check_fig_clip`。

三条配套：
· **图题的折行续行 bbox 必须并进图题框**。只取首行时，「上一条图题之下」
  停在首行底，图题第二行整条落进**下一幅**的裁框（实测图 3-2 顶上横着
  「Re-setting NAMCBPV at the rig to start position」）。
· **不能用 `page.get_text(clip=)` 求「框内还有什么字」**。MuPDF 对 clip 用的是
  部分包含判据：实测同样是图题顶端，4.8pt 落在框内会返回、2.7pt 就不返回。
  判据自己漏报比没有判据更糟（避坑 59）⇒ 取整页 span 自求矩形相交。
· **已含中文的 span 不算残留**。译文里本就嵌着 TMP／NC／O-ring 这类保留原文，
  实测「标准 TMP 斜向器总成」被当成残留英文，裁框一路收到源高的 52%。
· 收完还要回头确认**没把自己写的中文切掉**——撑开（中文可能比原文宽）与
  收紧（让开英文）是两股相反的力。

**101 ⚠ 词表键要按「实际分组」写，未译判据只能扫产出。**
多行图内标注按几何分组后查词表。键若按「源版看起来是一条引注」去写，
就可能与实际分组对不上 —— 实测两处：
· `("Break Bolt", "Break bolt shoulders", "on mill here.")` —— 「Break Bolt」
  是另一条独立引注（自带引线），中间隔 10.6pt，分组根本不会把它并进来；
· `("View from Outlet End", "(Inlet)")` —— 「(Inlet)」在
  「View from Piston Nozzle End」正下方（两者 x 心同为 219pt），归的是左边
  那一组；而且**活塞喷嘴端才是入口**，这条键连语义都挂错了。
键配不上就逐条回退，逐条又查不到，于是**静默回写英文**。

真正致命的是那条「未收录译名」的判据写成了
`not any(g["text"] in k for k in GROUP)` —— `in` 作用在**元组**上，
`'Break bolt shoulders' in ('Break Bolt','Break bolt shoulders','on mill here.')`
恒为真，分组根本没配上也报「已收录」。
⇒ **判据要落在产出上，不落在词表上**：查不到译名时原样回写的是英文，
   那就直接扫产出里有没有英文（保留原文另立白名单）。
   再配一个 `dump_keys()` 把**实际分组**打出来与词表逐条对照。

**102 CJK 折行会从西文词中间劈开。**
`wordWrap="CJK"` 认为任意两字符之间都可断。ReportLab 本来想避开 ——
断点落在 <0x3000 的字符上时它往回找空格或汉字，但**回溯只允许到行长的一半**
（`limitCheck = (lineStartPos+i)>>1`）。窄栏里「（第 2 代 RotaMaster）」的
那个空格恰好在前半段，于是回溯放弃、原地硬断，排出「（第 2 代 RotaMas ／ ter）」。
表格列宽的原子下限（`ATOM_RE` + `fit_cols`）保证的是「该词**单独一行**放得下」，
保证不了「前面还压着几个汉字时不被劈开」—— 那是断行算法的事。
⇒ `kinsoku2`：断点落在西文词内即回溯到词首（整行只有该词时才硬断）；
   两个入口（`dumbSplit` / `cjkFragSplit`）都要补，且要防 `i == len` 越界。
   同族缺陷：**括号里的单位组**要纳入原子（「近似重量（lb）」在 15pt 宽的列里
   被劈成「（l ／ b）」，而这一列本来一个原子都没有，也就没有列宽下限）。
   同族缺陷不止品牌名：实测负对照里还有「7-5/8-i ／ n」——**单位 in 被劈开**。

**102b ⚠ 「西文断词」的判据走了三稿，前两稿都不成立。**
· ①「上一行西文字母收尾 + 下一行小写西文字母起头」——**假阳**。
  纯英文段落在**空格处**正常折行，提取层看起来一模一样；四册共报 36 处，
  全是「positive displacement ／ motor」这类。靠「跳过附录页」压下去，
  等于把附录整块放行（避坑 59）。
· ②「再要求两截各自是本文档里独立出现过的词」——**假阴，而且是自证式的**：
  词表取自**成品自己**，而劈开的两截恰恰因为被劈开才各自单独成行，于是
  「RotaMas」「ter」双双进了词表，判据反过来给自己盖章。
  负对照（停用断行补丁重建）实测报 **0** —— 判据完全失效而毫无征兆。
· ③ 成立的那一稿：**看拼起来是不是一个词**。
  `RotaMas` + `ter` = `rotamaster`，是这份文档里真实存在的词 ⇒ 被劈开了；
  `displacement` + `motor` = `displacementmotor`，哪儿都不存在 ⇒ 正常折行。
  词表取**源版 ∪ 成品**，不需要外部词典，也不需要页码黑名单。
  负对照报 5 处（含两处单位 `in` 被劈）、正样本报 0 处。

⇒ 一般化：**判据写完必须做负对照** —— 把修复关掉重建一次，判据报不出来
  就说明判据本身是假的。第②稿五关全绿、看着很漂亮，实际一个也抓不到。

**103 ⚠ ReportLab 5 的 `PageBreakIfNotEmpty` 是个空壳。**
源码就一行 `class PageBreakIfNotEmpty(PageBreak): pass`，而
`handle_flowable` 只按 `isinstance(f, PageBreak)` 分派 —— 它与 `PageBreak`
**完全同义**。于是「每节前换页」遇上「上一节内容正好排满整页」，
就再撕出一张只有页眉页脚的空白页（实测某册第 13、28 两页）。
**关 7「空白页 = 0」看不见它**：判据要求「无文本且无图」，而页上有页眉页脚。

⇒ 自己按 `CondPageBreak` 的路子写一个：

```python
class SectionBreak(Flowable):
    def wrap(self, aw, ah):
        f = self._doctemplateAttr("frame")
        if f is not None and not getattr(f, "_atTop", True):
            f.add_generated_content(PageBreak())
        return 0, 0
```

⚠ **还要把紧挨在分页前的 Spacer 一并丢掉。** 表格后那点间距若被带到新页
顶上，`frame._atTop` 就成了假，上面这个判据照断不误 —— 空白页照旧。
折叠连续 PageBreak 的那个 `_nodup` 顺手一起做：

```python
if isinstance(x, (PageBreak, SectionBreak)):
    while out and isinstance(out[-1], Spacer):
        out.pop()
```

（`Spacer(w, h, isGlue=True)` 指望不上：ReportLab 5 的 `Spacer.__init__`
末尾无条件 `self.height = height`，把 glue 高度又写回去了。）

**104 「空白页 = 0」看不见只有一两行字的孤页。**
两种来源，处置不同：
· **正文尾页只剩一行** —— 判据能管：`check_thin_pages`（版心带内文本行 < 3
  且无图）。实测撤掉某个包装 Flowable 后段距恢复正常，正文正好多出一行，
  而其后紧跟硬分页，那一行独占一页。修法是把该节整节 `KeepTogether`。
· **长表尾页只剩一两行** —— 判据**管不住**：那一页上有表格线框，
  「无图」的豁免把它放过了。⇒ 改由**排版本身**管住：给长表装上「不留寡行」
  的分页（`appendix.NoWidowRows`），尾页不足 N 行就从上一页多挪几行下来。

一般化：**判据管不住的，就别硬写判据；改让排版层不产生那种版面。**

**105 ⚠ 把段落包进自定义 Flowable 会吞掉段前后距。**
页边修订条、色带、底纹这类「装配层附加物」常写成
`("wrap", lambda f: MyFlowable(f), 块)`，把 Paragraph 包一层再入流。
`Flowable` 不继承 Paragraph 的 `spaceBefore`/`spaceAfter`，于是被包过的那
几段之间**没有段距**，与同页其他段落松紧不一 —— 而全套闸门一处不报
（字在、字号对、不溢出、不残留英文）。
实测某节三个自然段挤成一坨，与同页下一节的段距明显不同，用户目检才发现。
⇒ 附加物要么画在 `canvas` 层（`onPage` 回调），要么在包装类里把内层的
`spaceBefore`/`spaceAfter` 显式转抄过来。

**106 ⚠ 徽标的软掩膜比基色图大 16 倍。**
封面徽标基色图 83×58 px，SMask 却是 1350×950 px —— 边缘全在掩膜里。
「掩膜与基图尺寸相同才合成」的写法跳过了它，提取出来是**黑底糊图**，超分也只是把糊图放大。

**107 超分图上的回叠：字号按行高、单字母不按横长比过滤、噪点不算引线。**
· 两行标注的检测框高是行高的两倍，字号按框高取就大一倍（「顶部注油孔」）⇒ 按**行高中位数**；

ST01/T01 是横向椭圆，竖向内半径小于编号框的半对角线；从半对角线起算，竖向射线跳过环、
抓到远处物体，环被画成竖长椭圆（实测 ST01×5、T01/T02×3 全歪）。

**109 ⚠ 环厚四向取最小。**
只沿一个方向扫「内腔边缘到亮」，引线所在方向把厚度拉到 40 px，"03" 画成实心黑盘。

**110 ⚠ 编号检测框可能是整个气泡连引线，框中心 ≠ 环心。**
T01 的检测框 112 px 宽（环 + 引线），中心比环心偏右 15 px；套用同规格半径、以框中心为环心，
新环偏右画出、旧环露出左半。⇒ 环心按环路径墨迹密度在框内搜索（受限 Hough）；填洞法的尺寸判据
要同时放行「内腔比框大」与「内腔比框小」。

**111 ⚠ 新环与旧环没对齐 → 旧环露出一截，闸门一处不报。**
用户报回「原部件序号还有保留」(`(T01`)。残留英文关扫文本层，这是像素。
⇒ 擦除按每 5° 实测外沿 +2 px 的多边形 ∪ 椭圆 +3 px；补画引线短截；
   `bubbles.residue_check` 常驻：新环外 +4/+8 px 圈上连续 ≥3 采样角的暗弧即残留，
   相邻气泡（25/26 相贴）与引线角簇要扣除，否则 5 处假阳把真残留淹没（避坑 59）。
   用户点名 2 处，判据跑的是全书 89 处。

## 八、最后一条，也是最重要的一条

**㊾ 闸门全绿 ≠ 没毛病。**

六道关只看「**写进去的东西**」：字写进去了吗、字号够吗、有没有重叠、
有没有残留英文、有没有豆腐块、源里的 token 还在不在。
它们看不见「**位置对不对**」。

实测：手册 B 第 43 页 21 条零件名被推出页面时六道关一处没报，
是拿 `git show HEAD:<成品> > old.pdf` 逐页渲染比对才发现的。

⇒ **引擎改动后必须做成品对成品的回归目检**，不能只看关卡。

同理，**用户报缺陷时给出的页号只是样本**。同一根因往往在几十页上同时发作
（实测「表格右侧多出竖线」= 981 处误检、涉 46 页）。
正确做法：**定根因 → 写一条覆盖全书的机器判据 → 给出「共 N 处、哪些页」的结论
→ 修完用同一判据复验为 0 → 把该判据固化成常驻自检**。
只修点名页既掩盖真实规模，也保证会复发。

## 九、跨机器与引擎整改（112~118）

**112 ⚠ extract 丢弃零面积线段 → 矢量图的引线不进图元簇。**
旧判据 `r.get_area() < 1 → continue` 本意是去噪点，但竖直/水平的引线宽或高为 0，
面积恒为 0，被整条丢掉。后果：图元簇只剩图形主体，引线末端的标注离簇 > 16pt，
「吸附图内小号标注」够不着 —— 裁框腰斩标签，标注作为正文滞留在 prose 里，
figures.json 的 labels 为空，覆盖判据也就无从报起。
⇒ 保留 ≥ 6pt 的短线段并加 0.5pt 厚度；跨版心 60% 以上的长横线仍视为分隔线丢弃。

**113 ⚠ 字体路径写死 `C:\Windows\Fonts\msyh.ttc`（9 个文件各写一份）。**
换到 macOS/Linux 或 Windows 装在非 C 盘的机器：ReportLab 路线 `KeyError('ZH')`
直接崩；叠印路线 `insert_font` 找不到文件时静默退化，成品满页豆腐块。
⇒ 一律 `fontkit.find(角色)`。两条隐含约束一并处理：ReportLab 只认 TrueType 轮廓
（Noto/思源 CFF 版抛 "postscript outlines are not supported"）；PyMuPDF 不能选 TTC
子字体（Noto CJK 的第 0 个是日文字形）→ 抽出子字体缓存。

**114 ⚠ 缺字闸门按 span 字体名 `yahei|^zh` 过滤。**
换到文泉驿/Noto/苹方后没有一个 span 的字体名匹配，闸门**一个字都不查**、恒报 0；
实测文泉驿缺 `•`，项目符号整列空白。另：PyMuPDF/ReportLab 写入字体里没有的字形时，
文本层留下 `\x00`（ord < 0x80 被旧判据跳过）。
⇒ 按 fontkit 实际解析出的字体逐 span 查各自 cmap，`\x00` 一律报缺字形；
符号用 `zhlib.pick_glyph("•●·")` 挑本机字体有的。负对照：用文泉驿写 `•`，判据必须报出。

**115 引擎往技能目录写东西 / 读客户资产。**
selftest 把 `_smoke.pdf` 写进 scripts/、driver 缺省徽标指向从未分发的客户徽标文件、
无徽标时抬头写死 `ACME DRILLING TOOLS`、残留英文缺省白名单含客户名 —— 换客户、
只读安装都会出错或把别家品牌印进成品。
⇒ 自检产物写临时目录；徽标/品牌文字/白名单逐文档传入（`Job.logo`、`logo_text`、
`whitelist_add`）。

**116 定级脚本与主干规则打架。**
主干已宣布「页数 ≥ 20 → 叠印」作废，`route.py` 仍按它给建议（24 页纯散文手册被判叠印），
`driver` 也只有 1:1 模式、R 级无从落地。
⇒ `route.py` 按 V2 逐页判 R/H/P/S；`Job(flow=True)` 流式装配，以内容对账 + 页数预算
代替「逐页实排 = 1 页」。**规则改了，脚本要同一天改** —— 模型会优先信脚本的输出。

**117 ⚠ Noto CJK（CFF）经 PyMuPDF 写入的两处静默失效。**
① 该字体 cmap 让 `-`、空格与 U+2011、U+00A0 共用字形，「量」「行」「理」与兼容汉字
U+F97E/U+FA08/U+F9E4 共用字形，PyMuPDF 反查取到的是别名 —— 渲染毫无异样，成品里却
搜不到「675-200-011」「数量」（实测第 2 轮评测：六道关全绿，是断言「数量」二字时才发现）；
② `subset_fonts()` 对 CFF 报 "Index bounds" 却不抛异常，成品 16 MB+。
两处都是闸门全绿。⇒ fontkit 给叠印选字体时把 CFF 与有 ASCII 别名的字体排到后面；
`doctor.py --fonts` 一次性转成 TrueType 并删掉 ASCII 别名映射（每个约 1 分钟，存缓存）；
`fontkit.save_subset()` 存完量体积、没瘦就换 `fallback=True`；新增 `checks.check_codepoints`
常驻闸门；`zh()` 把源文本里的 U+00A0/U+2011/U+00AD 归一。
叠印选中的字体只要有别名，`fontkit.find()` 自动做一份去别名副本（秒级、缓存），Windows 雅黑同样适用。
⚠ 别把别名删过头：按「最小码位」一刀切会删掉 `•`（它与 `·` 共用字形）→ 缺字形（实测）。
只删**非首选**码位（兼容汉字、部首、不换行变体、连字点…），两个首选码位共用时都留。

**118 ⚠ 图框线让 `tablefix.regions()` 把整张图纸认成一张表。**
图框的上下两条边横贯整页，按 x 跨度「互覆盖」聚族时把零件轮廓线也并进来；「后合并」
再把明细表并进这个整页大框 —— `fix_pages` 随即按源页英文把整张图的字重写一遍（实测毁页）。
⇒ `regions()` 剔除横贯 ≥ 93% 页宽的线；相邻两条行线之间必须有竖线贯通才算同一张表
（三线表没有竖线时退回旧判据 + 80pt 行距上限）；区域内至少 2 个词。
⚠ `hybrid_overlay.table_rects_grid` **故意保留**图框线：图纸整页落进表格区、全部走行级
通道，正是图纸需要的（剔除后段级通道把相隔 300pt 的「6-5/8 REG PIN」「… BOX」并成一条，实测）。
