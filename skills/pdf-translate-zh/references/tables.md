# 表格处理（tables）

> 主干见 `SKILL.md` §7。
> 用户原话：「对于表格，首先要定位绘制区域，然后将内容翻译好后，
> **真正使用表格技术重新编排**，然后在区域内渲染。目标是让表格更自然、
> 文本字号／样式在表内统一，不要出现跨列、对齐不统一等问题。」

---

## 1. 为什么逐格叠印**不够**

叠印的「格」来自 MuPDF 的行聚组，而它对表格并不可靠：

- 同一行相邻两格常被并成一条（`零件号数量`、`制图BY`、`CONSUMABLES PN`）；
- 每格又各自缩号求生 → 同一张表里**字号忽大忽小**；
- 并成一条的内容写进其中一格 → **内容跨列**。

这些都是**分格错了**的下游症状，在叠印层面只能一处处打补丁。

⇒ 换路：**先定位网格 → 逐格取文 → 译 → 按真表格统一重排渲染**（`tablefix.py`）。

---

## 2. 五步

```
① regions(page)          页面上的各张表（不合并）
② grid(page, clip)       按行带定列 → [(y0, y1, [列边界 x…])]
③ cells(src_page, gd)    按词心归格，得到干净的格内文本
④ 逐格查词表             整格 → 换行换空格 → 逐行，三段兜底
⑤ rebuild()              抹掉全表文字（线框不动）→ **全表统一字号**重排写入
```

调用：

```python
import tablefix
n, miss = tablefix.fix_pages(dst, src, TABLE_PAGES, lookup, keep,
                             base=8.0, drop_font=WM_FONT)
```

**次序很关键**：`fix_pages` 必须在**叠印之后**跑 ——
叠印负责翻译、tablefix 负责排版；它读到的已是中文，只重新分格与统一字号。

**逐页开启，不要全局开**（`TABLE_PAGES`，0 基）。步骤表这类「表里排散文」的页面，
全表统一字号会把长段落压得过小，须逐页目检后再加。

---

## 3. 核心：格内文本必须从**源页**取

这是最大的一个坑，也是「表头被并成一格」的真正根因。

成品页上的文字**已被叠印层按 MuPDF 的行聚组重排过**：同一行相邻两格
常已被并成一条并写进其中一格。实测 手册 D 第 6 页
`CONSUMABLES` + `PN` → 「零件号 消耗品」整条落在最右一格。

网格本身**是对的**（`ITEM | CONSUMABLES | PN` 三列俱全），错的是**文本来源**。

```python
tablefix.rebuild(page, bb, lookup, src_page=src_doc[pi], …)
```

线框与网格在源页与成品页上完全一致（叠印不动 line art），坐标直接通用。

> **走过的弯路（勿重走）**：曾以为是缺列边界，加了「行带列边界继承」——
> DESCRIPTION 列在别的行带上有内部竖线，补进来后 `STATOR, SS100`
> 这类整格被从中间切成 `STATOR,` + `SS100`，反而多出 6 行残留英文。已回退。

## 4. 七条几何判据（每条都对应一次实测失败）

### ① 按行带定列，合并单元格天然成立

行带取相邻两条水平线之间；该行带的列边界**只取纵向真正穿过这条行带的竖线**。
被合并的地方没有竖线穿过 —— 不必另写合并检测。

### ② 竖线必须**被行线横跨**

表旁插图的引出框线纵向很长、位置又贴着表，只按 x 范围收会被当成列。
实测 手册 C 第 6 页 x=321.1 混进 11 个行带，那些行带的列签名因此与众不同，
被 `_headers()` 判成表头，**整行加粗居中**。

⇒ 判据：该竖线要被 ≥ 5% 的行线在 x 上跨过。

### ③ 竖线的搜索范围要随 clip 变

`clip` 来自 `regions()`（按水平线 x 跨度求的粗框）→ 必须**向外扩张 36pt** 搜
（一张表里常有「只跨部分列」的半宽行线，全宽行线不足时表区会缩到半宽那一段，
最外侧的列被切在外面）。
`clip` 已过 `bounds()` 校正 → 要**收紧到 2pt**，否则把表外竖线补进来。

### ④ 主列线回补（**分子表统计**）

列分隔线常是分段绘出的，某几个行带上恰好断开，那几行的两列就被并成一格。
实测 手册 E 第 6 页 `O-RING` 与 `00100039` 同格，渲染成「O 形圈00100039」，全表 10 行如此。

⇒ 只回补「贯穿多数行带（≥ 60%）」的**主列线**。
统计必须**按子表分组**（按外边界归组）—— 混在一起会把零件表的列线补进消耗品表，
`WRENCH … CATCH RING` 被从 x=515.5 处切成两格。

### ⑤ 外边界要**剔除离群**

`bounds()` 取各行带外边界时不能用全局 min/max：表旁插图的引出框线
会落到个别行带上（实测 手册 E 第 6 页 x=321.1 只出现在 2 个行带），
按 min 会把表区左界拉到那里。⇒ 出现率 < 6% 的丢弃。

### ⑥ 表头识别用**结构**，不用内容

这些零件表没有粗体、没有底纹。唯一可靠的信号是结构：

- 每张（子）表的**第一个行带**是表头 —— 列边界元组一变即换了子表；
- 子表中途**重复出现**的同一条表头（`ITEM` 再来一次）也是表头。

**不能用「格内无数字」判** —— `A | GREASE | N/A` 一样没有数字。
列边界元组要按 **1pt 容差**归一（同一条竖线在不同行带上取到的 x 常差 0.2pt，
照原值比对会把每一处抖动都当成新子表）。
签名只用**成规模出现**（≥ 15% 行带）的竖线。

### ⑦ 对齐**按列**定，不按格

同一列里 `润滑脂` 靠左、`LOCTITE 290` 居中（后者被当成代号）——
一列之内两种对齐，正是用户点名的「对齐不统一」。

⇒ 该（子表）列的非表头格**全部**是数字／代号才居中，否则整列左对齐。
表头一律居中加粗。**单字符也算代号**（消耗品表的序号列就是 `A` `B` `D` `F`）。

## 5. `cells()` 的三个清理

- **保留行结构**：合并单元格里常一格列着好几条（4 种定子型号）。
  压成一行后既查不到词表，渲染出来也和原版对不上。
- **叠印去重**：原版常把同一串叠印两份，到这里变成 `CATCH CATCH`，
  键里没有这种重复串，整格必然未命中。按 `(x0, y0, 文本)` 去重。
- **分行按词心纵坐标聚类，不按基线**：同一视觉行里 `ROTOR, P100`（有下伸部，
  底 192.4）与 `(used w/ …)`（无下伸部，底 192.1）底边差得极小；
  而**换行**处 `stator)*` 的底边只比下一行高 2.4pt ——
  按基线 ±2.5pt 分行会把上一行的尾巴并到下一行，且排序后跑到行首，
  得到 `(used w/ SS300 stator)* ROTOR, P300 XL` 这种倒序串。

## 6. 水印会落进格里

格内文本取自源页，而源页上的水印还在，其字符会按位置落进各格，
渲染出「66057100 DRILLING」「O 形圈 ACME」这类混入（实测 手册 B 第 47 页 3 处）。

⇒ `drop_font=` 过滤。判据要**两条同时成立**：

- 词形属水印词表；
- 词框**有一半以上压在水印字符框上**（用 `font_char_rects()` 取**逐字符**框）。

只用 span 包围盒不行 —— 斜排水印的轴对齐包围盒是近 300pt 的大方块，
按它删会连带删掉 7 条正常零件名。
只按词形也不行 —— 版权栏里的 `ACME DRILLING TOOLS` 是正文。

## 7. `segments()` 的退化路径（**会整条丢线**）

CorelDRAW 导出的直线常被写成 `l` + 若干 `c`（控制点共线的贝塞尔）。
逐 item 取只能得到几个零长小段，`_coalesce` 也接不起来。

实测 手册 E 第 6 页零件表的 **5 条列线整条丢掉**（x=349/373/513/566/590，y 67~502），
表格一个行带都定不出。

⇒ 判据：**路径 bbox 若在某个方向退化成 0 宽，它本身就是那条线**。

```python
r = fitz.Rect(dr["rect"])
if r.width < 0.6 or r.height < 0.6:
    add(r.x0, r.y0, r.x1, r.y1)      # 整条路径 = 一条线
    continue
```

## 8. 抹除与写入

```python
for a, b, cols in gd:
    page.add_redact_annot(fitz.Rect(cols[0], a, cols[-1], b))   # 按**行带整条**
page.apply_redactions(images=fitz.PDF_REDACT_IMAGE_NONE,
                      graphics=fitz.PDF_REDACT_LINE_ART_NONE)
```

**按行带抹，不按格**：叠印层可能把文字写在错误的格里，甚至略微越出格边；
按格抹会留下碎片。行带之间的空当（插图区）不在抹除范围内，插图安全。

**全表统一字号** = 「所有格都放得下」的最大值：

```python
size = min(_fit(z, r, font, base, floor) for r, z, _, _ in items)
```

**纵向居中**：`insert_textbox` 从顶部起排，须先把写入框整体下移
`(行带高 − 文本高) / 2`，单行内容才落在行带正中。

## 9. 从零重建路线的表格（ReportLab）

- **一律用译文重建**，不截图。扫描件表单也要逐格转录重建，
  保留线框、表头底纹、填写栏与单位标注。
- **并排版式识别**：若某表的 bbox x 范围只占半幅（如 `x∈[270,540]`），
  说明原版是「图左表右」并排。照抄这个版式，否则该页必然溢出。
- 单元格内换行必须用 `<br/>`；`\n` 会被 `Paragraph` 吞掉。

### 9.1 ⚠ 原子记号不可断 → **列宽必须有下限**

`wordWrap="CJK"` 是中英混排的刚需（不开，中文长串被当成一个词，
放不下就整块挪行，实测首行只排三分之一）。代价是 ReportLab 认为
**任意两个字符之间都可断**：

| 记号 | 断成 |
|---|---|
| `2020-08-17` | `2020-08-1` / `7` ← 断行处还顶穿行高，压住表格线 |
| `0.005"~0.009"` | 从引号中间断开 |
| `5500 5625 6125` | `5500 56` / `25` |
| `ASTM E384` | `ASTM E3` / `84` |

这类记号是**工程标识，断开即改变含义**。而实测那张「修订历史」表
右侧连同版心两侧**都空着一大片** ——
**不是没地方，是列宽求解时压根没把记号宽度算进去。**

⇒ 分列前先给每列求一个**硬下限**（`render.fit_cols`，`grid_table` 自动调用）：

```
① 逐列量出最宽的原子记号（zhlib.ATOM_RE：日期／零件号／标准号／
   尺寸／数值+单位／多段编号），加左右内边距 → 该列下限；
② 总下限 ≤ 总宽 → 富余按原比例分配，每列不低于其下限；
③ 总下限 > 总宽 → 先向 grid_table(grow=…) 允许的两侧留白借宽；
   仍不够才等比压缩（此时是真的没地方，让它断）。
```

两处容易写错：

- **正则的择一是最左最先匹配，长模式必须排在前面。** 千分位
  （`\d+(?:,\d{3})+`）排在「数值+单位」之前，`10,000 psi` 就只认到
  `10,000`，剩下的 ` psi` 照断不误；多段编号（`200-675-1500`）也要排在
  区间模式（`30-35`）之前，否则只吃到 `200-675`。
- 叠印路线**症状不同、根因一样**。`_cjkwrap` 不会从记号中间断（拉丁词
  只在空格处断），但列给窄了它会**溢出**到邻列。
  `reflow._tbl_layout` 用同一条下限（`_atom_floor`）。

### 9.2 ⚠ 上下标：**压浅下沉量 + 补行距，缺一不可**

实测（reportlab 5.0，`Paragraph(...).frags` 直接量出来）：

| 标签 | 默认 rise | 默认 size |
|---|---|---|
| `<sub>` | **−0.5 × 母字号** | 0.8 × 母字号 |
| `<super>` | **+0.5 × 母字号** | 0.8 × 母字号 |

两处坑：

1. **`rise=` 属性是增量不是绝对值**，单位是 **pt**，且默认值按**母字号**
   算（同时给 `size=` 也不改变这一点）。要达到目标偏移 R，得写 `R − 默认值`。
2. **上下标只改字号与基线偏移，`leading` 纹丝不动。**
   实测 `tbl` 样式 7.4pt / 行距 9.6pt：下标探到基线下
   `0.5 + 0.8×0.21 = 0.668 em = 4.94pt`，而该行到次行字顶只剩 3.1pt ——
   **压进去 1.8pt**，`1100 HV(0.3 kgf)` 的下标贴死在下一行字头上。

⇒ 两件事一起做（`zhlib.fix_scripts` + `zhlib.lead_bump`，`render.P` 自动调用）：

- −0.5 em 是 ReportLab 的老默认，排版惯例约 **−0.20 em**（上标 +0.32 em）、
  字号 **0.72 em**。只压浅仍会蹭到次行，只加行距则行高白涨一截。
- 内容层只写朴素的 `<sub>0.3 kgf</sub>`（与字号无关），改写在 `P()` 里做
  —— 内容层不知道最终字号，而 rise 增量必须按字号算。

**标点与单位不要包进标签**：`HV<sub>0.3 kgf</sub>。` 才对。
写成 `HV<sub>0.3 kgf。</sub>` 会把句号一并缩小压低，读起来像下标的一部分。

> 旧办法「窄列里的多规格表头（`5500 5625 6125 6375 7250`）要**一行一个**」
> 现在只是**兜底**：列宽下限已能保住记号不断，手工拆行仅用于表头语义
> 本就该分行的场合。

## 11. 重建表绘制规范（审定条款，V3）

烧死位图表格**一律绘制重建，不以截图充当**（数值经视觉转录后必须与
原图逐项核对；矢量源表格直接按源页几何脚本抽取，禁止平文本转录）。
绘制规范：

- 字体一致（同表一个字号）；文本列**不加粗**；
- 数字右对齐、**保留千分号**、裸小数补前导 0（.028″ → 0.028″）；
- 表头：蓝底白字、常规字重、居中；跨列组头（最小/标称/最大）用
  SPAN 横向合并；组标签列（API Reg 扣型）竖向 SPAN 合并——
  ⚠ 竖向 SPAN 阻断跨页拆分，只用于确定单页的表；
- 窄列数字三禁：禁 CJK 断行、禁 splitLongWords、只允许显式 <br/>；
  区间在连字符后折行（0.39°– ↵ 1.0°），复合值在斜杠后折（0-60/ ↵ 30）；
- 单格整行的跨列标题行：SPAN 全宽居中、随表头着色——塞进首格会被
  挤成一列竖字（实测）。
