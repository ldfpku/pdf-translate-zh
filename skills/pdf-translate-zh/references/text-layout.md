## 1. 断行：`insert_textbox` **不会在中文里断行**

PyMuPDF 的 `insert_textbox` **只在空格处断行**。中文长串没有空格，
被整体当成**一个词**：放不下就整块挪到下一行。

实测 手册 A 第 6 页最后一段：

```
除装配与拆卸程序外，本手册还给出 API              ← 首行只排到 x=216
螺纹连接的修复判据。对特定零件进行无损检验（NDI）的检验表另以单独表单提供，索取最新表单请联系制造商   ← 次行排满到 x=552
销售或工程部门。
```

⇒ 自己按中文禁则**预折行**，再交给 `insert_textbox`（`hybrid_overlay._cjkwrap`）：

```python
_CJK    = "⺀-鿿豈-﫿　-〿＀-￯"
_NOHEAD = "、。，．；：）〕］｝」』】》〉！？%‰°″′"   # 不能出现在行首
_NOTAIL = "（〔［｛「『【《〈"                        # 不能出现在行尾
```

规则：**中日韩字符之间可断、拉丁词只在空格处断**；断点回退遵守两条禁则。

> ⚠ **旋转单元不折。** 它们的「行长」是框高，预折出的换行在 `rotate=` 下
> 按框宽堆叠 —— 实测 手册 B 第 43 页 21 条零件名有 14 条被挤出页面或截断。

### 1.1 ⚠ 从零重建路线：CJK 折行会**从西文词中间劈开**（避坑 102）

ReportLab 的 `wordWrap="CJK"` 是中英混排必须开的，代价是它认为
**任意两个字符之间**都可断。它本来想避开西文词：断点落在 <0x3000 的字符上
时会往回找空格或汉字 —— 但**回溯只允许到行长的一半**
（`limitCheck = (lineStartPos + i) >> 1`）。窄栏里
「（第 2 代 RotaMaster）」的那个空格恰好在前半段，回溯放弃、原地硬断：

```
（第 2 代 RotaMas
ter）                     ← 读者会以为是两个词
```

**列宽的原子下限救不了这一条。** `ATOM_RE` + `fit_cols` 保证的是
「该记号**单独一行**放得下」，保证不了「前面还压着几个汉字时不被劈开」——
那是断行算法的事。两者要一起上：

```python
import kinsoku2      # zhlib.register_fonts() 已自动装载
# 断点落在西文词内 → 回溯到词首；整行只有该词时才硬断
# 两个入口都要补：textsplit.dumbSplit（单 fragment）
#                paragraph.cjkFragSplit（含 <b>/<br/> 的多 fragment）
```

⚠ 补丁里必须防 `i == len(word)` 越界 —— 断在串尾时「后面没有字符」，
谈不上词被劈开，直接返回。

同族缺陷：**括号里的单位组要纳入原子**。表头「近似重量（lb）」在只有 15pt
宽的列里被劈成「（l ／ b）」，而这一列（数据只有 `264`）本来一个原子都没有，
也就没有列宽下限。⇒ `ATOM_RE` 收入 `[（(][A-Za-z0-9/·.%°µ]{1,10}[）)]`。

常驻闸门 `checks.check_word_split(out, src)`：把断开处的两截**拼起来**，
若拼出的串是「源版 ∪ 成品」里真实存在的词，就是被劈开的。
`RotaMas` + `ter` = `rotamaster` ✓ 报；`displacement` + `motor` =
`displacementmotor` ✗ 不报（那是空格处正常折行）。
两截各自都是合法英文片段，残留英文关、缺字关全部放行 —— 只有这一关看得见。

> ⚠ 别用「两截各自是不是本文档里的词」当判据：词表取自成品自己，
> 而劈开的两截恰恰因为被劈开才各自单独成行，双双进词表，判据自证。
> 负对照（停用补丁重建）实测报 0（避坑 102b）。

### 1.2 ⚠ 分页三条（ReportLab 路线，避坑 103/104/105）

**① 节前分页要用「本页已有内容才断」。** ReportLab 5 的
`PageBreakIfNotEmpty` 是空壳（`class …(PageBreak): pass`），与 `PageBreak`
同义；上一节正好排满整页时再撕一张空白页，而「空白页 = 0」看不见它
（页上有页眉页脚）。用 `builder.SectionBreak`。
**并且**要把紧挨分页前的 `Spacer` 丢掉 —— 它被带到新页顶上，`_atTop`
就成了假，分页件照断不误。

**② 长表要「不留寡行」。** 术语表几百行，ReportLab 只按「装得下就装」切，
尾页可能只剩一条词条。这一页判据管不住（页上有表格线框，"无图"的豁免
放过了）⇒ `appendix.no_widow(t, min_tail=6)`：尾页不足 6 行就从上一页
多挪几行下来。

**③ 别把段落包进自定义 Flowable。** 包装类不继承 Paragraph 的
`spaceBefore`/`spaceAfter`，被包过的段落之间没有段距，与同页其他段落
松紧不一，且全套闸门一处不报。附加物画在 canvas 层（`onPage`），
或在包装类里把内层的段前后距显式转抄过来。

## 2. 字号：同一行**向下取齐**

逐条各自缩号会让同一行里字号忽大忽小。用户点名多处：
「字体明显存在差异」「字号不一致」「插图/文本间隔类页面应统一字号」。

```python
# ① 先算每条**放得下的最大字号**
# ② 同一行取中位数作目标
# ③ 每条取 min(自身上限, 目标)  ← 只向下取齐，故恒能放下，不引入新溢出
```

**行的定义**：按框中心 y 除以 4 归组。

> ⚠ **旋转单元不参与同行取齐。** 纵开页上「同一视觉行」在去旋坐标系里
> 是同一**列**，按 y 中点分组会把整列零件名归成一「行」
> （实测 手册 B 第 43 页 21 条零件名的 y 中点全是 715），
> 取到的中位字号来自那一堆里最窄的一条，整列被压没。

**行高系数要分档**：折行时留 1.90 的安全余量（估算不准，宁小勿溢）；
文本自带换行、且各行都不折时真实需求只有 ~1.34。
一律用 1.90 会把多行算式压到 6pt。

## 3. 写入框向下**借用空白**

中文常比英文占更多行，写入框按英文墨迹框算就偏矮，只能缩号。
同一页里有的缩、有的不缩 → 字号忽大忽小。

⇒ 把框向下延到**正下方最近一个单元**之前，最多借 1.6 倍自身高。
借的是空白，不会压到别人；真压到了第五道关（重叠自检）会报。

```python
below = [u.y0 for u in units if u.y0 > kr.y1 - 0.5 and 横向重叠 > 25%]
lim = min(below) - 1.2 if below else kr.y1 + 1.6 * kr.height
kr.y1 = max(kr.y1, min(lim, kr.y1 + 1.6 * kr.height))
```

## 4. 列表

### ① 合并单元里的多条目必须**显式换行**

MuPDF 常把一份编号列表并成一个多行块。译文若用全角空格分隔，
渲染出来就是一长条，列表样式丢尽。

```python
# ✗ "6. 转子打捞环安装工具　7. 定心器　8. 轴承叠装壳体提升工具　9. 转子上扣工具"
# ✓
"6. 转子打捞环安装工具" + chr(10)
+ "7. 定心器" + chr(10)
+ "8. 轴承叠装壳体提升工具" + chr(10)
+ "9. 转子上扣工具"
```

> 用 `chr(10)` 而不是字面 `\n`：内容层常由脚本生成，
> heredoc / shell 会把字面反斜杠吞掉（见 `pitfalls.md` ㊳）。

### ② 层级与符号

- 一级用编号（`1.` `2.`），二级用 `▪`，缩进照原版；
- **项目符号本身属图形**，不译不动（`•` `▪` 是原版画上去的）；
- ReportLab 路线里 `("ol", items, mode)` 与 `("ol_from", start, items, mode)`
  的 mode 下标不同，写成统一的 `b[3]` 会让所有 `alpha` 静默退化成数字序号。

### ③ 「几何上恰好居中」的列表行会被居中判据抢走

实测 手册 A 首页三行说明在几何上恰好居中于页宽，
被 `centered_units` 认领后变成居中排版，与「无序列表左对齐」的要求相反。

⇒ 用 `LEFT` 记号（`chr(5)`）强制左对齐，压过几何判据。

## 5. 注意／警告框：**中文可以一行，不必同步英文行数**

用户原话：「对于注意类，中文本可以一行，不必按照英文原文格式去同步行数。
文本也是，不必严格按照英文原文严格对齐，造成译文阅读断裂！」

两种做法，按源单元的分法选：

**A. 源是一个单元** → 直接一行写完（中文比英文短 30%，通常放得下）。

**B. 源是两个单元**（各自有独立矩形，不能合并）→ **重新配平两行译文**，
让每一行各自读得通：

```
✗  某些马达配置需要拆开、把上轴承壳体从        ← 断在介词上
   传动件，以露出下驱动器／联轴节与分流器之间的连接。

✓  某些马达配置需要拆开、把上轴承壳体自传动件上抽出，
   以露出下驱动器／联轴节与分流器／分流器接头之间的连接。
```

配平的前提是 `join_wrapped` 没能把两行拼回去。若能拼回（多数情况），
就按 A 处理 —— 见 `overlay.md` §6 的句末判据。

## 6. 标题：原版的**下划线**改成**加粗**

工程文档常用「全大写 + 下划线」表达标题。下划线是**线条**（line art），
而抹除一律带 `LINE_ART_NONE` 以保住表格框，所以它原样留着 ——
中文比英文短，线就从字尾伸出去一截。

下划线在中文里本不是标题的表达方式。⇒ **线抹掉、标题改用加粗**。

判据（四条同时成立，宁漏勿误 —— 抹错线会在表格上留缺口）：

- 线在该单元墨迹的**正下方**（注意：常落在单元框**内**，因为框底含下伸部留白；
  只往框外找一律找不到 —— 实测 `CONNECTION INSPECTIONS` 框底 673.1、线在 671.5）；
- 线的 x 跨度**完全含于**该单元（±2pt）—— 表单的填写横线一律伸到标签右侧很远，据此排除；
- 线长 ≥ 单元宽的一半；
- 该单元本身是**标题级**的短行（宽 < 页宽 62%）。

抹除时**必须** `text=fitz.PDF_REDACT_TEXT_NONE` —— 抹除带正压在刚写好的
中文标题上，不豁免就把标题一起抹了。

## 7. 表单：标签右对齐**贴到填写线前**

原版这些标签是左对齐的，英文短、中文长短不一，照原位写出来右端参差，
与紧随其后的填写横线之间空隙忽大忽小。

⇒ 判据：**同一基线带内、紧接其右 ≤ 26pt 处有一条 ≥ 18pt 的横线** → 整条右对齐到线前 2pt。

```
✗  日期      ____________     工具序列号  ____________
✓      日期  ____________         工具序列号  ____________
```

实测 手册 C 第 2/31/32 页及其他三册同类页一次到位。

## 8. 译文里**不许出现 Markdown 星号**

写词表时顺手用 `**切勿**` 强调，会原样印进 PDF。
实测全项目 8 处（`**切勿**`／`**不得**`／`**累计**`）。

- 叠印路线：**没有内联粗体**，星号一律去掉（语气靠措辞，不靠标记）；
- ReportLab 路线：改 `<b>…</b>`（附录 A/B 走这条）。

交付前扫一遍：

```python
re.finditer(r"\*\*[^*\n]{1,20}\*\*", page.get_text())
```

⚠ 注意排除**原文自带**的星号（手册 I 第 19/20 页 `** 2.60**` 是脚注标记）。

## 9. 其他两条老规矩（ReportLab 路线）

- **表格里的裸字符串**：ReportLab 对未包 `Paragraph` 的裸串用默认西文字体，
  中文渲染成 ■■■。⇒ 所有单元格一律过 `Paragraph`。
- **填写栏下划线**：全角 `＿` 之间会断开，半角 `_` 在部分中文字体里也不连。
  ⇒ 用 `<u>　　　　</u>`（带下划线的全角空格），渲染为连续实线。

## 10. ⚠ 固定格式注记块：**一律重排，不要叠印**（`dwgnote.py`）

工程图标题栏的「UNLESS OTHERWISE SPECIFIED」注记、封面的密级声明、
表单的填写须知 —— 这类**格式固定的样板块**有三条共同特性，
使逐行叠印**必然**出错。实测 图纸族 J 四张 D 号图纸 12 页，一次全中。

### 三条特性

**① 换行是物理的，不是语义的。**

```
FINISH: 125∨ MAX.; 63∨ ON ALL          ← 一句话
THREADS & RELIEF SURFACES.             ← 被行边界切成两个待译单元
```

各自成句译出，成品读作「…适用于全部」「螺纹与退刀面。」两截。
末句 `ALL UNSPECIFIED DIAMETERS TO / BE WITHIN .005 TIR.` 同理，
且第二截为塞进原行框被**缩到极小、挤压变形**。

**② 列对齐靠前导空格。** 源里就是这样：

```
'DECIMAL:           .XXX   .005'
'                            .XX     .010'
```

`keyclean` 归一空白是必做的（不归一则词表永远命中不了），
归一之后 `.XXX/.XX/.X` 的小数点对齐**全丢**。

**③ `±`、`°`、粗糙度 `∨` 是矢量，不在文本层。**
词表若在译文里补一个 `±`，就与原矢量**重影**（实测「±2°-0′ **±** °」）；
不补则整列没有 `±`。两难 —— 因为问题根本不在词表。

> 附带第四条：**图纸叠印通道 `Overlay.add()` 的写入对齐默认居中**
> （对图框内的标签合适），而这一格是左对齐顶格 —— 整格文字被居中。

### 处置

整格抹掉重排（`reflow`），并且：

- **整句合并译出**，绝不按物理换行切开；
- 列对齐用 `("cols", [(列偏移em, 文本), …])` 定列块，
  **偏移以 em 计**，字号一降列距同比收窄；
- `±`/`°`/`′` 一律改用**真文字**（雅黑齐备，`check_glyphs` 复验为 0）；
- 抹除时开 `LINE_ART_REMOVE_IF_COVERED`：格内的 `±`/`∨` 矢量**完全落在
  框内**会被删，格子的**边框跨在框外**故保留。

### 三条实现层教训

1. ⚠ **解析只认源页。** 成品页上的英文锚点（`UNLESS OTHERWISE SPECIFIED`）
   早已换成中文，在成品上解析会**静默返回「本页无此块」**，看着像跳过了。
   ⇒ `fix(page, src_page)` 双页签名，装配流程必须传源页。
2. ⚠ **数值逐图解析，不写死。** 同一份样板各图取值不同 ——
   实测 0019 作 `.X ±.040`、0032 作 `±.030` 且角度是 `0.5°`。
   写死就会把甲图的公差印到乙图上，**六道关一处不报**。
3. ⚠ **区分大小字用「字号」，不用「行高」。** 粗糙度那两个数是 3.9pt、
   正文 5.9pt，但**行高**分别是 5.47 与 5.9 —— 阈值取 5.4 就差 0.07pt 失手。
   行高受升降部影响，字号才是稳定量。
   （另：这两个数**浮在行上方**，按 y 排序时排在 `FINISH:` **前面**，
   拿 `FINISH:\s*(\d+)` 去搜永远搜不到。）

### 可机器验证

肉眼看「对齐了没有」不可靠，写成判据：

```python
specs = [x for x, t in spans if re.fullmatch(r"\.X{1,3}", t)]   # 规格列
plus  = [x for x, t in spans if t.startswith("±")]              # ± 列
assert max(specs) - min(specs) < 0.05        # 小数点成列
assert max(plus)  - min(plus)  < 0.05        # ± 成列
assert "凡未注明的直径，全跳动均须在" in flat   # 末句成句，未被切断
```
