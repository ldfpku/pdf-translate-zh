# 目录（TOC）标准化与导航

> 主干见 `SKILL.md` §5。封面见 `cover.md`。
> 目录是**最容易被用户一眼挑出毛病**的一页 ——
> 本项目用户为「TOC 右侧页码没对齐」点名了**两次**，才挖到三层根因。
> 长文档（≥ 20 页）**强制**补跳转链接与书签。

**目录**：0. 先判断：叠印加记号，还是整页重排 · 1. 目录行的三段结构 · 2. 点引线：**必须实测收敛**，不能只估一次 · 3. 页码右对齐的**三层根因** · 3.5 整页重排：字号、缩进、引线（`reflow.py`） · 4. 跳转链接与书签（`toclinks.py`） · 5. 目录页码的**交叉回验** · 6. 目录条目本身的译法 · 7. 八道机器判据（`toccheck.py` / `tocsweep.py`）

---

## 0. 先判断：叠印加记号，还是整页重排

排版干预不可逆（抹掉就没了），先过判据，命中才动。判据看**源 PDF 的文本层**：

| 症状 | 处置 |
|---|---|
| 整列目录被导出成**单条超长串**（Word 域常见，实测 1,400~2,000 字符） | **必须整页重排** |
| 点引线残留在译文之间、页码落在行中央 | **必须整页重排** |
| 硬编码的单个省略号当引线、页码紧跟其后不右对齐 | **必须整页重排** |
| 页码是独立单元且被 `keep` 放行（纯编号） | 叠印 + `RIGHT` 记号即可 |
| 各条目结构完整、点引线可收敛 | 叠印 + `LEADER` 记号即可，**不重排** |
| 层级靠原版 x 坐标区分，但同级 x 不一致 | 重排（原版自身就不齐，叠印必照抄） |

原版没有目录就**不新造目录**。

## 1. 目录行的三段结构

```
6.3.2.2 固定弯壳体（FBH）  …………………………………  6-3-13
└──────── 标题 ────────┘  └── 点引线 ──┘  └ 页码 ┘
```

三段在提取层里**未必是同一个单元**。实测两种形态都遇到过：

| 形态 | 表现 | 处置 |
|---|---|---|
| **合并成一条** | 规范 F 把整列目录合并成一个 **1,400+ 字符**的超长串 | 按条换行 + `LEADER` 记号 |
| **页码独立成列** | 手册 A 的 `6-1-1` 是独立单元，且是纯编号 | `RIGHT` 记号 + 按基线与标题配对 |

## 2. 点引线：**必须实测收敛**，不能只估一次

点数是整数，且度量与实际渲染总有偏差。**一次估算下来各行落点能差 20pt 以上。**

```python
n = max(2, int(room / dot))          # 起点估算
for _ in range(24):                  # ← 关键：实测收敛
    w = _width(left + " " + "." * n + " " + right, size)
    if w > avail:
        n -= max(1, int((w - avail) / dot))
        if n < 2: n = 2; break
        continue
    if avail - w >= dot:
        n += max(1, int((avail - w) / dot))
        continue
    break                            # 距右边界不足一个点宽 → 收敛
```

**逐行处理**：目录常是一整块多行文本，每行各自要把页码顶到右边界。
只处理第一处 `LEADER` 就只有首行对齐。

实测右端离散（改为收敛后）：

| 文档 | 改前 | 改后 |
|---|---|---|
| 手册 A | 24 pt | **2.6 pt** |
| 手册 B | — | 2.4 pt |
| 手册 C | — | 2.0 pt |
| 规范 F | — | 4.4 pt |

## 3. 页码右对齐的**三层根因**

用户点名两次。前两次修的都是表层，第三次才见底：

### ① 几何右对齐判据**抢了目录块**

目录的右端本该由点引线负责。再叠一层「整行右对齐」，
填充算短一点就把整行往右推，**左边缘随之参差**。

⇒ 带排版记号（`LEADER` / `RALIGN` / `RIGHT` / `LEFT`）的条目
**一律自己管对齐，不参与几何判据**：

```python
if zh.startswith(RIGHT) or zh.startswith(LEFT):
    ctr.discard(idx); rgt.discard(idx)
if LEADER in zh or RALIGN in zh:
    ctr.discard(idx); rgt.discard(idx)
```

### ② 页码是独立单元，且被 `keep` 跳过

手册 A 的 `6-1-1` 属纯编号，`keep` 规则直接放行 → **原样留着**，自然左对齐参差。

⇒ 新增 `RIGHT` 记号：内容不变、只改对齐。

```python
def lookup(text, ctx=None):
    if _is_toc_num(text, ctx):        # 目录区里的纯编号
        return chr(4) + text.strip()  # RIGHT 记号
```

### ③ 各级条目的**框宽本来就差 20pt**

一级标题的框比三级标题宽 —— 各自右对齐到自己的框，右端仍不齐。

⇒ **同页所有 `RIGHT` / `LEADER` 条目的写入框右端取齐到公共 x**：

```python
_ridx = [i for i, it in enumerate(items)
         if it[2].startswith(RIGHT) or LEADER in it[2]]
if len(_ridx) > 1:
    _xmax = max(items[i][1].x1 for i in _ridx)
    for i in _ridx:
        items[i] = (…, fitz.Rect(r.x0, r.y0, _xmax, r.y1), …)
```

## 3.5 整页重排：字号、缩进、引线（`reflow.py`）

命中 §0 的重排判据后，整块抹掉、按块 DSL 重排。三条要点：

### ① 基准字号是**搜索所得**，不预设

全目录**同一个基准字号**：先按上限试排，装不下整体降一档（步长 0.2），
而不是逐条各取各自的最大值 —— 后者正是「同页字号忽大忽小」的成因。

> ✗ 不要写「一级 10~10.5pt、二级 9.5~10pt」。目录条目数各册差异极大
> （实测 43 条 ~ 129 条）。固定 10pt 在 129 条时必然溢出一页，
> 而溢出会让其后所有页的页码标签整体错位（坑 ㉔），且**页码看着仍然连续**。

级间差别只用两样表达：**字重**（章节级粗体）与**缩进**。
字号至多降一档（细目级 ≤ 基准 × 0.94），且**同级必须同号**。

### ② 缩进用步长制，随字号缩放

```
第 n 级左界 = 版心左界(实测) + (n − 1) × 步长
步长 = k × 基准字号            k 默认 1.60（约 1.5 个汉字宽）
```

- **版心左界必须实测**，不写 `72pt`；右界同理（实测 543.0，写死 540 就差 3pt）；
- 字号降了缩进跟着降，比例不变；
- **双栏目录要调小 k**：单栏净宽只有 ~270pt 时，1.6 倍步长会让三级条目挤到
  放不下，取 1.3 左右（实测 手册 I 用 12pt / 9.6pt ≈ 1.25）。这正是步长制
  相对写死 16/32pt 的好处。

**同级条目的左界必须完全相同（离散 = 0）**，可机器验证（§7 关 E）。

**图表条目至少比其所属章节深一级**，严禁与正文章节标题同级顶格。

### ③ ⚠ 点引线要**从右往左**画

点数是整数，取整余量必然存在（最大一个点宽 ≈ 0.5 em）。若从标题末尾向右
铺点，余量落在**引线右端与页码之间** —— 各行参差直接暴露在最显眼的位置。

⇒ **引线右端锚定在页码左侧的固定间隙处、向左延伸，余量留在标题一侧**
（那里本就是空白，看不出来）。

```python
rend = x1 - nw - gap                 # 引线右端锚点（页码左侧）
used = tx + _w(t, tsz, tb) + gap     # 引线左端下限
n = max(2, int((rend - used) / dot))
ops.append(("t", rend - n * dot, y, "." * n, ...))   # ← 从 rend 往左量
```

页码按**右端对齐**即可，不强求等宽字形 —— 右对齐已保证右端齐，
中文字体的比例数字视觉上更自然。两端留白取 `0.30 × 基准字号`，随字号缩放。

### ④ ⚠ 多区域目录：`LINKS` 会被逐次清空

`render()` 每次试排都清空 `LINKS`，`run()` 逐区域调用 ⇒ 前面区域的链接
被后面冲掉。实测 手册 I 双栏目录 52 条只建出 **13** 条，
且**六道关一处不报**（链接是注记，不进文本层）。

⇒ 取 `reflow.ALL_LINKS`（`run()` 跨区域累积），不要取 `LINKS`。

## 4. 跳转链接与书签（`toclinks.py`）

长文档必做。产出两样：PDF 内部跳转链接（点标题跳到正文）+ PDF 书签（侧边导航栏）。

```python
import toclinks
n_link, n_bm = toclinks.add(pdf, toc_pages=[2, 3, 4], offset=4)
```

### 两种页码体系，处理完全不同

| 体系 | 例 | 办法 |
|---|---|---|
| **连续页码** | 规范 F 印刷页 1…92 | 物理页 = 印刷页 + 偏移，`offset` 由调用方给 |
| **分节页码** | 手册 A `7-4-2` | 算不出来 —— 必须按页眉 `<标签> \| P a g e` **实扫建表** |

```python
toclinks.add(dst, toc_pages, offset=0, use_labels=True)   # 分节页码
```

`page_labels(doc)` 扫全书页眉，建「标签 → 物理页」映射。

### 三条不能省的细节

1. **必须在合并附录之后加。** 附录一并进来，物理页号全变，链接全废。
2. **标题行与页码行要按基线配对。** 手册 A 的标题与页码**不在同一文本块**
   （页码右对齐成独立一列）—— 不配对则**一条链接都建不出**。
3. 标题过短（< 2 字）的行跳过，避免把页眉页脚也当成目录条目。

实测产出：规范 F **129 链接 + 129 书签**；手册 A **67 链接 + 67 书签**。

### ⚠ 四条后来补上的硬伤

**① `add()` 必须幂等。** 装配流程用 `saveIncr` 增量写，重跑一次就再叠一层
链接 —— 实测 手册 A 的「134 条链接」实为 67 条各两份，规范 F 的 258 条实为
129 条各两份。`set_toc` 会整体替换书签，故**链接数 = 书签数 × 2** 是这个
毛病的指纹。⇒ 加链接前先清掉本页已有的 `LINK_GOTO`。

**② 书签层级要由编号推出，不能一律压成一级。** 122 页、深到 `6.3.1.3.3` 的
手册做成一层平铺的书签树，等于没有导航：

```python
def _level(title, prev):
    m = re.match(r"^(\d+(?:\.\d+)*)(?=[\s　]|$)", title)
    if m:
        parts = m.group(1).split(".")
        while len(parts) > 1 and parts[-1] == "0":   # `1.0` 是顶层
            parts.pop()
        return len(parts)
    if re.match(r"^\s*[图表]\s*\d", title):           # 图表条目不与章节同级
        return max(2, prev + 1)
    return 1
```

**③ PDF 大纲一次不能跳两级。** 目录的**视觉缩进**完全可以跳（实测「表格与
图表」是二级、其下的「表 1」按四级缩进），做成书签立即
`ValueError: bad hierarchy level`。⇒ **条目与顺序 100% 照搬，层级归一到
「至多深一级」，视觉缩进不动。** 原始规范里那句「书签结构与 TOC 的文本及
层级 100% 对应」做不到，也不该做。

**④ 原版目录的页码可能是错的。** 未刷新的 Word 域很常见。实测：
规范 G 三条各差 1 页（`Jar Load … 6` 实为 7、`Core Drilling … 23` 实为 24、
`Directional Drilling With Motor … 25` 实为 26）；手册 A 的
`7.3.2 Flexshaft … 7-3-1` 实为 `7-3-2`。照抄就把跳转落到前一页。
⇒ `toclinks.add(..., fix={"7.3.2": "7-3-2"})`，并逐条记入**附录 A 甲**。
这类错只有「落点回验」（§7 关 C）查得出来。

### 文件编号索引（没有页码的目录）

有的手册由若干分册装订而成，目录右列不是页码而是**文件编号**
（`DM6754`／`675G2R PL`／`G2R w/ CLAW INSP`）——「印刷页 + 偏移」无从谈起。
但每个分册的每一页都印着自己的编号，于是
「条目编号 → 首个**页眉**印着该编号的页」就是准确的落点，
而且比按页码更稳（分册页数一改，页码全变，编号不变）：

```python
n_link, n_bm = toclinks.code_links(dst, toc_pages=[2])
```

⚠ **只认页眉带、且要求那一行以编号开头。** 拿整页文本做子串匹配会错两次：
短码互相包含（`ASSY` 命中每一个 `DISASSY` 页）；正文里的交叉引用（零件表
提到 `IC7011`）会抢在真正的分册首页之前。实测这两条让 4 册各错 3~4 条落点，
**六道关一处不报**。

⚠ **链接矩形纵向要内缩。** 行框含升部降部，实测高 11.5 而行距只有 10.85 ——
照抄行框，相邻两条就压叠 0.7pt，点上一条可能跳到下一条。内缩 0.6pt 即可。

## 5. 目录页码的**交叉回验**

1:1 同源版式下，任一逻辑页多排一页，其后所有页的标签就整体错位 ——
**页码看着仍然连续**，只是内容与页码对不上，目检极难发现。

⇒ 除「逐页实排自检」外，还要做**目录条目 ↔ 实际页面内容**的交叉回验：
按目录里的页码翻到该物理页，检查该页是否真的含有该标题。

## 6. 目录条目本身的译法

- **同一标题在目录与正文里必须同名**。办法：目录与正文共用一张
  「章节标题表」，由「带编号」「无编号」两条规则 + 一条裸标题回退处理。
  实测 手册 A 三种形态共存：
  `6.3.2.2 Fixed Bend Housing (FBH) … 6-3-13`（带编号）、
  `General Assembly Drawing … 5-1`（无编号）、
  `HS&E`／`Appendix`（正文裸标题）。
  不共用一张表就会写出三份不同译名。
- 点导线长度随标题长短而变，**同一标题在不同页点数都不同**。
  `keyclean.norm_leaders()` 先把 3 个以上连续点归一为单个 `…`，键才稳定可查。
- 目录页若把点导线**单独排成一个文本项**（马达手册 即如此），
  该项全为点与空格，会被 `keep` 规则直接判为「保留不译」，无须特殊处理。
- ⚠ **同一标题在目录与正文里必须同名。** 实测四处不同名，全靠「落点回验」
  才发现：规范 G 目录写「震击器闭锁机构」、正文排作「闭锁机构」；
  规范 F 目录写「精整与标识／螺纹防护／钢印代码」、正文排作
  「涂装与标识／螺纹保护／标识喷涂代号」。页码都没错 ——
  错的是读者**按目录检索不到**。改目录去就正文（正文出现次数多，动它风险大）。
- ⚠ **两端对齐的标题会被切成逐词单元**（坑 ㉟ 在标题上的再现）。
  实测 手册 I 的 `6.1 Adjustable Assembly Field Procedures` 在源里是四个独立
  span（`6.1 Adjustable ` / `Assembly ` / `Field ` / 次行 `Procedures `），
  叠印逐段翻译、各写各的原位，成品成了「6.1　可调　　　总成　　　现场／程序」。
  这类标题**恰恰是目录的跳转落点**，故由「落点回验」抓到。
  ⇒ 该处走重排通道合成一条完整标题。

## 7. 八道机器判据（`toccheck.py` / `tocsweep.py`）

> 六道关看的是**全书**，且从不看「位置对不对」。封面与目录恰恰是**位置**
> 决定成败、且用户一眼就能挑出毛病的两页。

| 关 | 判据 | 抓什么 |
|---|---|---|
| A | 目录条目数 = 跳转链接数 = 书签数 | 漏建、**重建**（幂等失守） |
| B | 同页链接矩形两两不重叠；矩形内确有文字 | 点上一条跳到下一条 |
| C | 每条链接的目标页含该条目的关键词（或编号） | **原版页码陈旧**、OFFSET 算错、译名不一致 |
| D | 同页页码右端 x 离散 ≤ 一个点宽 | 右对齐没做到 |
| E | 左界相近（< 一个步长）的条目必须**完全**对齐 | 缩进没取齐 |
| F | 封面与目录页的保留项在成品上仍在 | 抹除连坐（封面最危险） |
| G | 这两页白名单外的英文行 = 0；文字不越出页面 | 漏译、越界 |
| H | 成品各块的对齐方式与源页一致 | 居中的被排成了左对齐 |

```bash
python <skill>/scripts/tocsweep.py <repo-root>     # 按册登记页号后全库跑
```

**判据本身不能冤枉人**，否则人就学会无视它。本项目为此改了六处：

1. **A 关的条目数不能拿链接数充数** —— 那样「有目录、一条链接都没建」会
   0=0=0 报绿，正是最该抓的情形。要从页面上实际认得出的条目行数取。
2. **C 关抽不出关键词就只验页号在界内** —— 「第 1 节」这类标题没有连续两字
   的可比对片段，硬报就是假阳。
3. **C 关的条目文字要取「行中心落在矩形内」的那一行**，不能用 `get_textbox`
   兜底 —— 它把与矩形相交的一切都返回，抽出来的编号来自下一条。
4. **C 关要按索引键分流**：末尾是页码就验标题关键词，是文件编号就验编号。
   拿标题关键词去验编号索引必然全军覆没（条目文字是描述，不会原样出现在
   落点页上）。
5. **D 关要先按栏聚类再逐栏判齐** —— 双栏目录天然有两个右界
   （实测左栏 x≈300、右栏 x≈545，整页一起量得 245.6pt）。
6. **F 关比对要去掉全部空白再做子串测试**，且剥掉尾随标点 ——
   译文把半角 `,` 换成全角 `，`，`590-2280,` 这类号码每册都会误报一次；
